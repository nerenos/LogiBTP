- Contexte : liens entre modules dans [MODULES.md](MODULES.md) ; contexte condensé de chaque partie dans son `CLAUDE.md` (`socle/`, `modules/<nom>/`, `client/`, `src/`, `db/`), chargé quand on travaille dans le dossier.
- Sous-dossiers du client à contexte propre : `client/src/calcul/`, `client/src/app/structure/`, `client/src/app/ressources/`, `client/src/app/terrain/`, `client/src/app/bibliotheque/`. Référence détaillée de chaque partie (inventaire des fichiers, modèle de données, routes), lue à la demande : `documentation/modules/<NOM>.md`. Historique des lots et des dates : [JOURNAL-LOTS.md](documentation/JOURNAL-LOTS.md).
- Dépendances externes par module (npm, NuGet, polices) : [DEPENDANCES.md](documentation/DEPENDANCES.md), généré par `npm run rapport-dependances` à relancer après tout ajout ou mise à jour.
- Tâches à faire et décisions reportées : [TODO.md](TODO.md) (à mettre à jour quand une tâche est faite ou reportée ; une tâche faite passe dans `documentation/TACHES.md`, réservé aux humains).

- Répondre et documenter en français ; code, commentaires et noms en français (sauf API techniques).
- Architecture : `socle/` (sans métier) → `modules/<nom>/` (classes mères, méthode patron) → cœur (`src/`, `client/`, `db/`) qui spécialise. Un module ne dépend jamais du cœur ; le module Métré ne dépend pas du module Document.
- Moteurs miroirs JS / C# : `MoteurDocument` (`modules/document/js/src/moteur-document.js`, `modules/document/dotnet/LogiBTP.Documents/Calcul/MoteurDocument.cs`) et `MoteurDevisBtp` (`client/src/calcul/moteur-btp.js`, `src/LogiBTP.Calcul/MoteurDevisBtp.cs`). Toute règle modifiée l'est dans les deux, avec un cas dans les jeux du module ou du cœur, puis `npm test`, `npm run exporter-resultats` et `dotnet test LogiBTP.slnx`.
- Jamais de `Number` pour un montant côté JS (decimal.js) ; une seule fonction d'arrondi par moteur (demi vers l'infini).
- Codes (statuts, natures, états, erreurs testées par l'interface) : jamais en dur ; `js/src/codes.js` de chaque module (objets `Object.freeze`) ↔ `Codes.cs` (constantes), parité vérifiée par le `CodesTests` du module (`Constantes.Ecarts` de `LogiBTP.Socle.Testing`) ; communs aux modules dans le socle (`NIVEAU_NOTIFICATION`, `PROFIL`, `ACTION_DROIT`, `NIVEAU_CONFIDENTIALITE`, `VariablesEnv` ; refus du paramétrage : `u.ExigerAdmin()`) ; cœur : `client/src/app/codes.js` ↔ `src/LogiBTP.Domaine/Codes.cs` (`TYPE_FICHE`, `TYPE_DOCUMENT`, `MODULE_FACULTATIF`… ; adresses par `urlFiche` / `urlDocument`) ; seul le SQL des requêtes garde ses littéraux.
- Noms de colonnes du DDL partout (snake_case préfixé) ; les propriétés C# en PascalCase s'y mappent automatiquement. Colonnes génériques (`modules/document/js/src/types.js`) et BTP (`client/src/calcul/colonnes-btp.js`) alignées sur les entités (des tests le vérifient).
- Schéma géré par les scripts SQL de chaque module (`modules/*/db`) puis du cœur (`db/`), pas de migrations EF ; les colonnes métier s'ajoutent par `ALTER TABLE` dans le cœur.
- Une base par société (sous-domaine) : les contextes EF prennent la connexion de `SocieteCourante` par requête ; tout cache singleton dépendant du schéma est indexé par base ; ce qui est propre à une société hors de la base (documents de la GED) est rangé sous le nom de sa base (`SocieteCourante.Base`).
- Pièces valables (module Rentabilité, [analyse](documentation/conception/ANALYSE-MODULE-ANALYSE.md), lot 0) : toute somme de pièces ou tout précédent passe par `v_document_valable` / `f_document_valable(id, annulees)` (module Document `019p`) ou `PerimetreDocuments` en C# — verrouillée, indice de référence, non REMPLACE —, jamais par `ent_verrouille` seul ; coûts des achats ventilés par chantier des lignes (`v_document_chantiers_part`, `db/255`), chantiers d'une pièce dans `document_chantier` (`db/257`) ; chargé d'affaires d'une affaire `aff_responsable_ind_id` (`db/256`) ; unités : ligne transformée d'unité différente validée seulement avec la conversion de l'article (`UNITE_TRANSFORMEE`, liens convertis), article de stock sans conversion refusé (`STK_UNITE`) : `Btp/UnitesLignesBtp.cs`.
- Serveur : toute route `/api` se rattache à un nœud de droits dans `SpecialisationDroitsBtp.Routes` (sinon 403 `DROIT_NON_DECLARE`) ; tout nouveau script SQL s'ajoute au manifeste `db/installation/scripts.txt`.
- Interface, dans tout le projet (modules compris) : **aucun texte, icône ni couleur en dur** (`texte()`, `icone()`, variables du thème : module Personnalisation) ; fenêtres par `<dialog>` (`confirmer` / `alerter` / `saisir` / `ouvrirModale` du socle), jamais `confirm()`, `alert()`, `prompt()` ; dates par `activerDates` / `completerDate` ; combos par `creerCombo` (jamais de `<select>` simple) ; raccourcis par `declarerRaccourcis` + `actionDe(e, groupe)`, jamais de test de touche en dur ; préférences d'affichage dans le `localStorage`, jamais en base (sauf `preferencesCompte`). Détail : `client/CLAUDE.md`, `socle/CLAUDE.md`.
- Secrets de l'installation dans `.env` (hors dépôt, modèle `.env.exemple`) : détail dans `modules/installation/CLAUDE.md`.

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:
- When graphify-out/graph.json exists, run `graphify query "<question>"` before your first grep, search or source-file read for a codebase question, and put this rule in every subagent prompt that explores code. Read raw files only for lines the graph or an earlier read already located. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
- A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected. Do not flag it as churn or suggest skipping the graph rebuild or its hooks.
