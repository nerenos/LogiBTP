Module Annuaire Structure JS .NET DB Tests

Structure du module

  • db/ : Schéma SQL complet (070_annuaire_schema.sql)
  • dotnet/ : Implémentation C# (LogiBTP.Annuaire)
  • js/ : Implémentation JavaScript/TypeScript
  • tests/ : Tests unitaires

Faiblesses identifiées

  • Manque de contraintes d'intégrité référentielle sur certaines tables de liaison
  • Absence d'index composés pour optimiser les requêtes fréquentes de recherche par critères multiples
  • Pas de déclencheur pour mettre à jour automatiquement les champs de modification (per_modifie_le, ind_modifie_le)
  • Manque de validation côté base pour les codes postaux et numéros de téléphone selon les pays
  • Absence de journalisation détaillée des modifications critiques (changement de casquette, modification de SIREN/SIRET)
  • Pas de contraintes CHECK pour valider les formats d'email, d'URL ou de numéros de téléphone

Informations manquantes à ajouter en BDD

  • Table pour stocker les préférences de notification par utilisateur
  • Champ pour tracker l'origine des données (import manuel, API externe, synchronisation)
  • Table d'héritage pour gérer les différents types de pièces jointes aux coordonnées
  • Champs pour stocker les métadonnées de géolocalisation (latitude, longitude) des adresses
  • Table pour gérer les historiques de changement de statut (actif/inactif) avec période de validité
  • Champ pour stocker le score de fiabilité des données basé sur les sources et validations
  • Table pour gérer les relations de dépendance entre personnes (ex: filiale, filiale de)

Recommandations d'amélioration

  • Ajouter des déclencheur pour automatiser la mise à jour des champs *_modifie_le
  • Implémenter des index GIN sur les colonnes JSONB pour améliorer les performances de recherche
  • Ajouter des contraintes CHECK pour valider les formats d'email, téléphone, SIREN, SIRET
  • Créer une table d'audit spécifique pour les modifications sensibles des données tiers
  • Implémenter un système de versionnement léger pour les coordonnées partagées
  • Ajouter des champs pour tracker le RGPD (date de consentement, objet du traitement)

Faiblesses identifiées

  • Absence de déclencheur pour empêcher la modification des éléments utilisés dans des documents actifs
  • Pas de validation pour garantir la cohérence entre les différents scénarios de prix

Informations manquantes à ajouter en BDD

  • Table pour stocker les historiques détaillés des changements de fournisseur avec raison
  • Champ pour tracker l'origine géographique des éléments (pays d'origine, zone de préférence)
  • Table pour gérer les substitutions d'équivalents acceptés entre éléments
  • Champs pour stocker les caractéristiques environnementales (empreinte carbone, recyclabilité)
  • Table pour gérer les certificats et normes associés aux éléments (ISO, CE, etc.)
  • Champ pour stocker la date de dernière réévaluation du prix de marché
  • Table pour gérer les contrats-cadres avec fournisseurs et leurs conditions particulières

Recommandations d'amélioration

  • Ajouter des contraintes CHECK pour valider la cohérence des prix (PV_net <= PV, etc.)
  • Implémenter des déclencheur pour empêcher la suppression des éléments référencés
  • Ajouter des index sur les colonnes de recherche fréquente (ele_code, ele_libelle)
  • Créer une vue matérialisée pour les statistiques de rotation des stocks
  • Implémenter un système de validation des scénarios de prix avant enregistrement
  • Ajouter des champs pour tracker l'obsolescence programmée et les dates de fin de vie
