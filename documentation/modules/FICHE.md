# Module Fiche – référence détaillée

Référence lue à la demande (hors contexte par défaut). Les règles que le code doit respecter sont dans [CLAUDE.md](../../modules/fiche/CLAUDE.md) ; une règle modifiée l'est là, l'inventaire ici.

## Dépendances
- Dépend de : `@logibtp/socle` (`echapper`, `formatLibre`, `htmlSur`, `editerLibelle`, `creerCombo`), `LogiBTP.Socle` (`Chiffrement`), `LogiBTP.Socle.Web` (`Utilisateur`, `ExceptionMetier`, `JsonCalcul`), `LogiBTP.Socle.Testing`. Jamais du cœur ni d'un autre module (la GED arrive par l'option `ged`).
- Fournit le contrat `IChronosFiches` du socle (`ServiceFiche.AttribuerAsync`) : code attribué hors de la fiche (tiers provisoire et compte particulier du module Annuaire, projet créé depuis une demande du CRM).
- Utilisé par : cœur C# (`SpecialisationFicheBtp` dans `src/LogiBTP.Api/Btp/SpecialisationsElements.cs`, `AddModuleFiche<SpecialisationFicheBtp>`, `api.MapModuleFiche()` ; `SpecialisationListeBtp` lit `ServiceFiche.Verrou`) ; client : `FicheLogiBTP extends FicheBase` (`client/src/app/fiches/fiches.js` : `FicheSalarie`, `FicheMateriel`), `fiche-element.js` (`FicheElement`), `fiche-annuaire.js` (`FichePersonne`, `FicheIndividu`), `fiche-structure.js` (`FicheProjet`, `FicheAffaire`, `FicheChantier`, `FicheMarche`) ; page `/fiche/:type/:id` (`pages/fiche.js`, `?copie=1` = copie).

## Modèle de données
- `type_fiche` (`tyf_code`, `tyf_libelle`, `tyf_table`, `tyf_cle`, `tyf_colonne_proprietes`, `tyf_definition` JSONB : titre, sous_titre, sections/groupes, champs).
- `droit_fiche` (`drf_profil`, `drf_type`, `drf_action` ∈ VOIR, MODIFIER, DEBLOQUER, CONFIDENTIEL, SUPPRIMER, MODIFIER_CODE) ; module Droits : action `MODIFIER_CODE` des nœuds `fiches/{type}`.
- Chrono (`tyf_definition.chrono` : `champ`, `prefixe`, `format`, `raz` A / J, `portee` (champ qui sépare compteurs et unicité : bibliothèque d'un élément), `parent` (champ de la fiche parente du jeton {PARENT}), `variante` + `variantes` [{ valeur, libelle, prefixe }] (sens d'un marché)) ; format paramétré `chrono_fiche` (`chf_type`, `chf_variante`, `chf_prefixe`, `chf_format`, `chf_raz`) ; compteur `compteur_fiche` (`cpf_type`, `cpf_variante`, `cpf_portee`, `cpf_exercice` (0 = jamais remis à zéro), `cpf_dernier`) ; {PARENT} : pas de compteur, rang = plus grand rang des codes du parent + 1.
- `parametre_champ_fiche` (`pcf_obligatoire` : rendre obligatoire un champ facultatif ; `pcf_confidentiel` : rendre confidentiel un champ du logiciel, hors champs gérés) ; `champ_supplementaire` (`chs_type_donnee` texte/nombre/booleen/date/liste/motdepasse, `chs_format`, `chs_options`, `chs_requete` (liste par SELECT), `chs_section` (onglet de la définition, sinon Informations complémentaires), `chs_groupe` (cadre titré), `chs_ordre`…).
- `verrou_fiche` (`vef_type`, `vef_id`, `vef_utilisateur`, `vef_jeton` UUID par onglet, `vef_depuis`, `vef_renouvele`) ; `journal_confidentiel` (`jcf_champs` TEXT[]).
- Types du cœur (`TYPES_FICHE` dans `client/src/app/fiches/definitions.js`) : salarie (`salarie`), materiel (`materiel`), element, personne, individu, projet, affaire, chantier, marche ; `DROITS_FICHE`, `PARAMETRAGE_FICHE`, `ficheDeLigne({ type, id })` (ligne de liste → fiche).
- Groupe d'un onglet (`sections[].groupes[]`) : `code`, `titre`, `champs`, `largeur` (`LARGEUR_GROUPE` ↔ `LargeursGroupe` : `plein` = toute la largeur), `disposition` (`DISPOSITION_GROUPE` ↔ `DispositionsGroupe` : `grille` par défaut, `flex` = champs à la suite à la largeur de leur contenu, classe `fiche-flex`) ; nouvelle valeur : code JS + C# (parité `CodesTests`) et règle dans `fiche.css`.
- Champ : `code`, `colonne` (programme) ou supplémentaire, `type` (texte, zone, html, json, nombre, booleen, date, liste, motdepasse), `format` (email, telephone, code_postal, 999.99, regex:…), `longueur`, `obligatoire`, `confidentiel` (+ `confidentiel_parametre`), `lecture_seule`, `saisie: 'creation'`, `non_copie`, `options`, `requete`, `section`, `groupe`, `reference`, `defaut`, `gere`.

## Points de spécialisation
- C# `SpecialisationFiche` : `CodeParentChronoAsync(type, champ, valeur)` (texte du jeton {PARENT} : code du chantier d'un marché), `NettoyerHtml(html)` (champs de type html nettoyés avant écriture ; cœur : liste blanche du module Document, aucun script), `ExpirationVerrou` (2 min), `DelaiRequeteMs`, `DroitsSupplementaires`, `ValiderMetier` (→ `ErreurChamp`), `AvantEcriture` / `AvantEcritureAsync` (`aEcrire` reçoit des colonnes calculées), `AvantSuppressionAsync`, `Constructeur(type)`, `LireGeresAsync`, `ValiderGeresAsync` (avant écriture, id null en création), `EcrireGeresAsync` (après la ligne, dans la même transaction : un refus annule aussi la ligne ; par défaut refuse tout champ géré), `ApresEcritureAsync(type, id, creation, u)` (après la validation de la ligne et des champs gérés : suites comme le géocodage du cœur).
- Cœur : `SpecialisationFicheBtp` délègue element → `ElementsBibliotheque.AvantEcriture`, salarie → `SalariesAnnuaire.Synchroniser`, personne/individu → `ServiceAnnuaire` (`LireGeres`, `ValiderGeres`, `EcrireGeres`, `ControlerPersonne`), projet/affaire/chantier/marche → `Intervenants` (champ géré `intervenants`). `AvantSuppressionAsync` → `SuppressionFiches` ; `ApresEcritureAsync` : chantier et restaurant géocodés (`Geocodage`).
- JS `FicheBase` : `sousTitre`, `champsNonCopies` (non_copie + gérés), `valeursCreation`, `validerMetier`, `rendreInformations`, `actionsSupplementaires` → `[{ libelle, titre, action, visible, raccourci }]`, `ongletsSpecifiques` → `[{ code, titre, rendre(corps, { modifiable }), dans? }]`, `rendreChamp(champ, valeur)`, `groupeVisible(groupe, section)` (groupe affiché ; tous par défaut), `apresChargement`, `definirValeur(code, valeur)`. Options : `conteneur`, `fournisseur`, `type`, `id`, `mode`, `message`, `ged`, `peutParametrer`, `actions` (boutons de l'hôte dans la barre, hors saisie : imprimer…), `surEnregistre`, `surFerme`, `surSupprime`.
- Barre de la fiche : boutons courants en icône seule (`icone` ; libellé et explication dans la bulle `title`, `aria-label`) ; Enregistrer et Annuler gardent leur libellé.
- Code à chrono (`definition.chrono`) : champ vide en création avec le code prévisionnel en texte indicatif (italique, atténué ; ⇥ le reprend pour le modifier), contrôle en direct après 300 ms (`fournisseur.code`, état sous le champ : déjà utilisé par la fiche… — lien par l'option `ouvrirFiche({ type, id }, e)` —, disponible), prévisionnel recalculé quand la portée, le parent ou la variante change (`definirValeur` ou saisie) ; à l'enregistrement, 409 `CODE_PRIS` → « Utiliser le prochain code disponible » (`confirmer`, puis enregistrement avec lui) ; en modification, champ en lecture seule sans `droits.modifier_code`.
- Raccourcis clavier : groupe `fiche` déclaré par le module (`declarerRaccourcis` du socle : modifier F2, annuler, copier, supprimer, synthèse, confidentiel, paramétrer, onglets Alt+1…9, précédent, suivant ; personnalisables dans la page des raccourcis de l'application), écouté sur le document tant que la fiche est affichée (`#brancherClavier`, retiré à la fermeture ou quand le conteneur n'est plus dans la page) ; une action de l'hôte ou d'une spécialisation porte `raccourci` (code complété par l'hôte dans le groupe `fiche`, ex. `imprimer` du cœur) ; touches rappelées dans la bulle du bouton. Clic droit dans la fiche (`#menuFiche`, hors champ, lien et composant qui ouvre son propre menu — `defaultPrevented`) : actions visibles de la barre avec leurs touches, onglets précédent et suivant.
- Méthodes de `FicheBase` : `ouvrir`, `recharger`, `rendre`, `modifier({ forcer })`, `controlerVerrou`, `annuler`, `copier`, `reveler`, `enregistrer`, `parametrer`, `supprimer`, `fermer({ sansConfirmation })` ; lecture : `valeur`, `propriete`, `valeurs()`, `proprietes()`, `modifiee`, `masques`.
- Définition renvoyée au client (`DefinitionFicheDto`) : `type`, `libelle`, `titre`, `sous_titre`, `sections`, `champs` (obligations du paramétrage incluses), `supplementaires` (onglet « Informations complémentaires », code `+supplementaires`), `droits { voir, modifier, debloquer, confidentiel, supprimer }`.
- Masques confidentiels : `FicheDto.Masques` = code (programme) ou `+code` (supplémentaire). Mots de passe : jamais envoyés (valeur null), `FicheDto.Secrets` liste ceux qui sont enregistrés (code ou `+code`) ; 👁 de la fiche → `revelerSecret` (droit VOIR, et CONFIDENTIEL si le champ l'est), journalisé ; jamais copiés, ni journalisés par `Reveler`.
- Listes par requête des champs du logiciel (`requete` de la définition du type) comme des champs supplémentaires : options résolues par `ResoudreOptions`, requête jamais envoyée au client.
- Listes par requête : `ServiceFiche.OptionsRequete` (transaction READ ONLY annulée, `statement_timeout`, 1 000 valeurs, colonne 1 = valeur, 2 = libellé), essayée à l'enregistrement du paramétrage, résolue dans `Definition`, `Enregistrer`, `Creer` (`ResoudreOptions`) ; la définition envoyée ne contient jamais la requête. Hors ligne : option `requete(sql)` du fournisseur mémoire (sinon options saisies).
- Chiffrement : `Chiffrement` du socle (injecté ; `AddChiffrement` dans `Program.cs`, sinon non configuré) ; valeur `chiffre:v1:…` en base, déchiffrée dans `LigneComplete` (validation et révélation en clair, en mémoire), chiffrée juste avant l'écriture (`ChiffrerSecrets`, `ProprietesJson`). Sans chaîne : paramétrer un mot de passe est refusé (422 `CHIFFREMENT`).
- `FournisseurFicheMemoire` : types `{ definition, lignes, cle, proprietes, derivees(ligne), geres: { lire, valider, ecrire } }` (mémoire : `types.<type>.geres`).

## Routes HTTP (sous `/api/fiches/{type}`)
- `GET /definition` ; `GET|PUT /parametrage` (PUT : ADMIN).
- `POST ""` (créer), `GET /{id}?confidentiel=`, `PUT /{id}` (`DemandeEnregistrement` : `jeton`, `h`, `valeurs`, `proprietes`, `confidentiel`), `DELETE /{id}` (droit SUPPRIMER).
- Chrono : `POST /code` (`{ code, valeurs, id }` → `{ previsionnel, pris: { id, code } }` ; droit MODIFIER), `GET /chrono` (une ligne par variante : préfixe, format, remise à zéro, dernier rang, prochain code), `PUT /chrono` (`{ variante, prefixe, format, raz, dernier }`, administrateur).
- `POST /{id}/confidentiel` (révéler, journalisé) ; `POST /{id}/secret` (`{ champ }` → `{ valeur }` : mot de passe en clair, journalisé) ; `POST /{id}/verrou` (`{ jeton, forcer }`), `DELETE /{id}/verrou?jeton=`.
- Erreurs : 422 `VALIDATION` (liste d'`ErreurChamp`), `CHAMP`, `VALEUR` (23505 = doublon), `REQUETE` (liste par SQL), `CHIFFREMENT`, `CODE_PRIS` (code modifié déjà porté), `CHRONO_FORMAT` ; 409 `VERROU_PERDU`, `FICHE_MODIFIEE`, `FICHE_EN_MODIFICATION`, `FICHE_UTILISEE` (clé étrangère), `CODE_PRIS` (création : `details { code, pris, propose }`) ; 403 `ACCES_REFUSE` (code changé sans MODIFIER_CODE).
