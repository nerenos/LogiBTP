# Module Stock – référence détaillée

Référence lue à la demande (hors contexte par défaut). Les règles que le code doit respecter sont dans [CLAUDE.md](../../modules/stock/CLAUDE.md) ; une règle modifiée l'est là, l'inventaire ici.

## Dépendances
- JS `@logibtp/stock` : `@logibtp/socle` (décimaux). .NET : `LogiBTP.Stock` (règles), `LogiBTP.Stock.Web` → `LogiBTP.Socle.Web`, EF Core Npgsql. Jamais du cœur ni d'un autre module.
- Utilisé par : cœur (`Btp/StockBtp.cs` : `SpecialisationStockBtp`, `MouvementsStockBtp` appelé par `SpecialisationBtp`), client (`client/src/app/stock/`, bloc Stock de `panneaux-btp.js`).

## Structure
- `js/src/stock.js` ↔ `dotnet/LogiBTP.Stock/ReglesStock.cs` (jeu `tests/cas/01_stock.json`) : `minute` (date-heure à la minute, date seule = minuit), `stockA` (dernier comptage de date-heure ≤ T, plus les mouvements après lui jusqu'à T ; mouvement de la même minute qu'un comptage = déjà compté), `ecartComptage` (compté − stock juste avant).
- `js/src/valorisation.js` ↔ `dotnet/LogiBTP.Stock/ReglesValorisation.cs` (jeu `tests/cas/02_prix.json`) : `valoriser` (événements de tous les lieux rejoués par minute — mouvements, comptages, réévaluations — : entrée valorisée = PMP pondéré par le stock total, le prix si ce stock était nul ou négatif, 6 décimales, et dernier prix d'achat ; comptage = quantité du lieu remplacée ; réévaluation = PMP saisi ; historique du PMP par mouvement), `valeurUnitaire` (méthode PMP / DERNIER_PA, repli = PA de la bibliothèque signalé `REPLI`), `METHODES_VALORISATION`.
- `js/src/inventaire.js` ↔ `dotnet/LogiBTP.Stock/ReglesInventaire.cs` (jeu `tests/cas/03_inventaire.json`) : `controlerLot` (lignes de tous les bordereaux cumulées par article dans l'ordre de première ligne comptée ; ligne sans quantité ignorée ; `INV_DOUBLON_EMPLACEMENT` en avertissement ; erreurs `INV_QUANTITE_NEGATIVE`, `INV_PRIX_DIFFERENTS`, `INV_PMP_SANS_PRIX` ; prix unique, « Appliquer au PMP » seulement avec un prix, commentaires joints par « ; »), `MESSAGES_INVENTAIRE`.
- `js/src/projection.js` ↔ `dotnet/LogiBTP.Stock/ReglesProjection.cs` (jeu `tests/cas/04_projection.json`) : `projeter` (stock présent + événements ENTREE / SORTIE cumulés par jour ; daté avant aujourd'hui = aujourd'hui et `retards` ; entrées avant sorties le même jour ; réservation servie avec le disponible de son jour, manque couvert le premier jour où le disponible redevient ≥ 0 ; `points`, `premiere_rupture`, `minimum`), `minimumJusqua`, `proposer` (sous le mini → maxi, sinon mini, − disponible, au conditionnement supérieur).
- `db/093c_stock_approvisionnement.sql` (rejouable) : `stk_seuil` (mini, maxi, délai par article et lieu), `stk_lieu_parametre` (délai des propositions, frise).
- `dotnet/LogiBTP.Stock.Web/ServiceApprovisionnement.cs` : `ServiceApprovisionnement` (paramètres du lieu, seuils, `ProjectionAsync`, `SyntheseAsync` — réservé, attendu, disponible, première rupture, plus bas à l'horizon, proposition —, `CommanderAsync`) ; horizon des propositions = délai de l'article dans le dépôt (`stk_seuil`), sinon délai de l'article fourni par la spécialisation (`ArticleStock.DelaiJours` ; cœur : tarif principal, sinon `ele_delai_livraison`), sinon délai du dépôt ; spécialisation : `PrevisionsAsync`, `ApprovisionnementsAsync`, `CreerCommandesAsync` ; `MapApprovisionnement`.
- `js/src/tracabilite.js` ↔ `dotnet/LogiBTP.Stock/ReglesTracabilite.cs` (jeu `tests/cas/05_tracabilite.json`) : `numeroLot`, `repartirLots` (quantité de la ligne en valeur absolue, lots facultatifs : reste `sans_lot` ; erreurs `TRA_NUMERO_VIDE`, `TRA_QUANTITE`, `TRA_DOUBLON` sans casse, `TRA_SERIE_UNITE`, `TRA_DEPASSE` ; avertissement `TRA_INCOMPLET` pour un article suivi), `dateLimiteLot` (périssable : fabrication sinon réception + durée en jours ou mois), `stockParLot` (dernier comptage : toutes ses lignes de la même minute par lot, un lot absent à 0 ; puis mouvements postérieurs par lot ; lots croissants puis sans lot), `MESSAGES_TRACABILITE` ; codes `js/src/codes.js` ↔ `Codes.cs` (`SUIVI_ARTICLE`, `UNITE_DUREE`, `CodesTests`).
- Lot S24-b : `proposerLots` ↔ `ProposerLots` (FEFO si périssable — date limite, périmés écartés —, sinon FIFO par date d'entrée, puis identifiant ; reste non couvert) ; `controlerLot` ↔ `ReglesInventaire.Controler` : `lot` des lignes, `lots` du comptage (cumul par numéro sans casse ; reste sans lot), doublon d'emplacement par lot ; `db/093g` : `bli_lot`, `stk_comptage_lot` (répartition d'un comptage), `cpt_lot_id` retirée ; `ServiceTracabilite` : `ComptagesParLotAsync`, `StockLotsAsync` (route `GET /articles/{id}/lots/{lieu}?date=`), `LotParNumeroAsync`, lot `INITIAL` posé par un comptage neutre à l'activation du suivi ; `ServiceInventaire` : génération d'une ligne par lot en stock (et du sans lot), validation qui crée les lots inconnus et répartit le comptage.
- `db/093f_stock_tracabilite.sql` (rejouable) : `stk_article_suivi` (suivi, périssable, durée, unité), `stk_lot` (`ux_lot_numero` : article, fournisseur, numéro sans casse), `mvt_lot_id`, `cpt_lot_id`, `mvt_tracabilite` retirée ; `ServiceTracabilite.cs` (`SuiviAsync`, `DefinirSuiviAsync` — gestion —, `LotsAsync` : lots avec stock par lieu, sans lot, unité ; `ModifierLotAsync` ; routes `GET|PUT /articles/{id}/suivi`, `GET /articles/{id}/lots`, `PUT /lots/{id}`) ; `SpecialisationStock.NomsTiersAsync`.
- `db/093e_stock_inventaire_piece.sql` (rejouable) : `lin_ent_id` (pièce des écarts du lot), `lin_extourne_ent_id` (contre-passation) ; `SpecialisationStock.ApresValidationLotAsync(db, lot, ecarts, u)` (écarts lus par `EcartsAsync` après la validation) et `ApresAnnulationLotAsync` ; `LotDto.Piece`, `Extourne`.
- `db/093d_stock_dotations.sql` (rejouable) : `stk_article_dotation` (type EPI / OUTILLAGE, durée de vie en mois) ; `ServiceInventaire.DotationArticleAsync` / `DefinirDotationAsync`, type et durée renvoyés par `ArticlesAsync`.
- `db/093b_stock_inventaire.sql` (rejouable) : `stk_lot_inventaire` (lieu, date-heure à la minute, état BROUILLON / VALIDE / ANNULE, `lin_micro`), `stk_bordereau` (critère de génération JSONB, compteur), `stk_bordereau_ligne` (quantité vide = non compté, théorique à la génération, prix, appliquer au PMP, commentaire), `cpt_lin_id` et `rev_lin_id` (comptages et réévaluations d'un lot), `stk_marque` (EPI, OUTILLAGE, TOURNANT fournies) et `stk_article_marque`.
- `db/093_stock.sql` (rejouable) : `stk_parametre` (méthode), `stk_emplacement` (arbre par lieu, code complet unique), `stk_article_emplacement` (emplacements habituels), `stk_mouvement` (date à la minute, quantité signée en unité de stock, prix d'une entrée valorisée, `mvt_provisoire` et `mvt_prix_initial` d'une réception non facturée, `mvt_prix_ent_id` = facture qui a fixé le prix, `mvt_pmp` calculé, origine, pièce et ligne, tiers, salarié, `mvt_tracabilite` réservé aux lots et numéros de série), `stk_comptage`, `stk_reevaluation`, `stk_valeur` (valorisation courante), `stk_a_valoriser` (articles marqués par les triggers `f_stk_marquer`), `f_stk_quantite(article, lieu, t)`, `v_stk_stock` (ensembliste).
- `dotnet/LogiBTP.Stock.Web/ServiceStock.cs` : entités, `StockDbContext`, `SpecialisationStock` (`LieuxAsync`, `ArticlesAsync`, `PiecesAsync`, `ApresValorisationAsync`, `PeutGererAsync`), `ServiceStock` (paramètres, emplacements, `ValoriserAsync` / `ValoriserEnAttenteAsync` — avant toute lecture des valeurs —, `RevaloriserToutAsync`, `ReevaluerAsync`, `FicheArticleAsync`, `EtatAsync` — quantités par `ReglesStock`, valeur à la date par rejeu —, `MouvementAsync`), `Extensions` (`AddModuleStock<T>`, `MapModuleStock`).
- `dotnet/LogiBTP.Stock.Web/ServiceInventaire.cs` : entités des lots, bordereaux, marques ; `ServiceInventaire` (`LotsAsync`, `CreerLotAsync` — date à venir refusée —, `ModifierLotAsync`, `SupprimerLotAsync` (brouillon), `LotAsync` (bordereaux, lignes, contrôle `ReglesInventaire`), `AjouterBordereauAsync`, `EnregistrerBordereauAsync` (lignes remplacées, emplacements du lieu), `GenererAsync` (EMPLACEMENT : emplacements habituels dans la zone ou en dessous ; FAMILLE (sous-familles comprises), MARQUE, STOCK : articles mouvementés ou comptés dans le lieu ; un bordereau par valeur ou un seul ; quantité théorique à la date du lot), `EcartsAsync` (stock juste avant hors comptages du lot, valeur à la date), `ValiderLotAsync` (erreurs refusées, `STK_COMPTAGE_EXISTANT` si un autre lot a compté l'article dans le lieu à la même minute, un comptage par article, réévaluation datée du lot), `AnnulerLotAsync`, `CorrigerAsync` (micro-inventaire : lot d'une ligne validé d'office), marques (`MarquesAsync`, `EnregistrerMarquesAsync` — retirée portée = désactivée —, `MarquesArticleAsync`, `MarquerAsync` en masse), `ArticlesAsync` (gérés en stock avec marques), `FamillesAsync`) ; `MapInventaires` (sous le groupe `/stock`) ; spécialisation : `ArticlesGeresAsync`, `FamillesAsync`, `ArticlesDeFamillesAsync`.

## Routes HTTP (préfixe `/api/stock`, module activé par société)
- `GET|PUT /parametres` { methode } ; `GET /lieux` ; `GET|PUT /lieux/{id}/emplacements` ; `GET /lieux/{id}/etat?date=&zeros=`.
- Inventaires : `GET|POST /inventaires?lieu=`, `GET|PUT|DELETE /inventaires/{id}`, `POST /inventaires/{id}/bordereaux|generer|valider|annuler`, `GET /inventaires/{id}/ecarts`, `PUT|DELETE /bordereaux/{id}`, `POST /articles/{id}/corriger` { lieu, quantite, emp, prix, appliquer_pmp, commentaire, date }.
- Marques et articles : `GET|PUT /marques`, `GET /articles/{id}/marques`, `POST /marquer` { articles, ajouter, retirer }, `GET /articles`, `GET /familles`.
- Approvisionnement : `GET|PUT /lieux/{id}/parametres|seuils`, `GET /lieux/{id}/approvisionnement`, `GET /lieux/{id}/projection/{article}`, `POST /lieux/{id}/commander` { lignes: [{ ele, unites_achat, fournisseur_id }] }.
- Dotation d'un article : `GET|PUT /articles/{id}/dotation` { type, duree_mois }. Magasin et dotations des salariés : routes du cœur `/api/stock/magasin/*` (`MagasinBtp.cs`).
- `GET /mouvements/{id}` ; `GET /articles/{id}` ; `POST /articles/{id}/pmp` { pmp, commentaire, date } ; `PUT /articles/{id}/emplacements` [ids] ; `POST /revaloriser`.
- Gestion (paramètres, emplacements, réévaluation) : `PeutGererAsync` (cœur : administrateur ou membre d'un service LOGISTIQUE).
- Borne et saisies à valider (lot 5) : routes du cœur (`StockBorneBtp.cs`) : `/api/pointage/borne/stock` (publique), `/api/stock/bornes/{id}/depot`, `/api/stock/magasin/a-valider`.
