# Module Authentification – référence détaillée

Référence lue à la demande (hors contexte par défaut). Les règles que le code doit respecter sont dans [CLAUDE.md](../../modules/authentification/CLAUDE.md) ; une règle modifiée l'est là, l'inventaire ici.

## Dépendances
- JS `@logibtp/authentification` : le socle seul (dictionnaire : textes des règles). .NET : `LogiBTP.Authentification` (règles, empreintes, jetons), `LogiBTP.Authentification.Web` → `LogiBTP.Socle.Web`, EF Core Npgsql. Jamais du cœur ni d'un autre module.
- Utilisé par : cœur (`SpecialisationAuthentificationBtp`, `Program.cs` : intergiciel, routes, commande `comptes`) ; client (`pages/connexion.js`, `pages/compte.js`, session de `Application`).

## Structure
- `js/src/regles.js` ↔ `dotnet/LogiBTP.Authentification/ReglesCompte.cs` : `controlerPseudo` (3 à 50 caractères `[a-z0-9][a-z0-9._-]*` après mise en minuscules, réservés refusés), `controlerMotDePasse` (longueur minimale en points de code, 128 au plus, courants refusés sans casse, pseudo absent), `etatCompte` (SERVICE, INACTIF, EXPIRE le lendemain de la fin de validité — jour UTC —, SANS_MOT_DE_PASSE, VERROUILLE, A_CHANGER, ACTIF ; connexion pour ACTIF et A_CHANGER), `controlerCompte` (personne autorisée, profil connu et permis, fin de validité obligatoire et pas passée), messages ; `suggererPseudo` (JS seul) ; jeux `tests/cas/01_pseudo` à `04_compte`.
- `dotnet/LogiBTP.Authentification/HachageMotDePasse.cs` : PBKDF2-SHA256 (`pbkdf2-sha256$itérations$sel$empreinte`, 210 000 itérations, `AReprendre` pour relever le réglage à la connexion), vérification en temps constant, mot de passe provisoire lisible, jeton de session (32 octets, base64 URL) et son empreinte SHA-256 (seule conservée).
- `dotnet/LogiBTP.Authentification.Web` : `Donnees.cs` (`Compte`, `SessionUtilisateur`, `JournalConnexion`, `ParametreAuthentification`, `AuthDbContext`), `ServiceAuthentification.cs` (paramètres, connexion, connexion de test, session lue avec cache de 30 s par base, déconnexion, changement de mot de passe, journal ; `OptionsAuthentification` : section `Authentification`), `SpecialisationAuthentification.cs` (`Profils`, `ProfilParDefaut`, `PersonneAsync`, `RechercherPersonnesAsync`, `PseudoLibreAsync`, `ApresEcritureAsync` ; `PersonneCompte`), `Extensions.cs` (`AddModuleAuthentification<T>(base, section)`, `UseAuthentificationSession`, `MapModuleAuthentification`, `HttpContext.Session()`), `CommandeComptes.cs` (commande serveur de secours), `ServiceComptes.cs` (gestion des comptes par un administrateur : liste et état, détail avec journal, création pour une personne autorisée avec mot de passe provisoire rendu une fois, modification, réinitialisation, déverrouillage, recherche des personnes ; `CompteDto`, `CompteSaisi`, `CompteEtMotDePasse`, `PersonneEtCompte`).
- `db/005b_authentification_securite.sql` (rejouable) : usurpation (`ses_usurpe_cpt_id`, `ses_usurpation_fin`, `ses_usurpation_motif`, paramètre `usurpation` { minutes, notifier }, événements USURPATION, USURPATION_FIN, USURPATION_ACTION) ; lot 3 : `cpt_uuid`, type API (`cpt_adresses` : CIDR permises), `cpt_double_facteur` (choix de l'utilisateur), `ses_uuid`, `ses_absolue_le`, `ses_mac_id`, `ses_api`, `jeton_remplace` (jetons de rafraîchissement remplacés), `machine_connue`, `code_connexion`, `ip_exclue`, paramètres `double_facteur` { mode AUCUN | ADMIN | TOUS }, `exclusion_ip` { echecs, minutes, durees }, `session.duree_max_heures`.
- `dotnet/LogiBTP.Authentification/Adresses.cs` : `Prefixe` (IPv4 entière, IPv6 par /64, IPv4 encapsulée = IPv4), `DansPlages` (CIDR), `PlagesInvalides`.
- `dotnet/LogiBTP.Authentification.Web/JetonsAcces.cs` : JWT HMAC-SHA256 (clé dérivée de la chaîne de l'installation par `Chiffrement.Empreinte`, aléatoire par processus sans chaîne), 5 min (API : 15 min), session complète dans le jeton, liée à la base (`SocieteCourante.Base`) ; `Invalider()` relève l'époque (révocation immédiate, D26) ; `ServiceAuthentification.Securite.cs` : rafraîchissement rotatif, machines connues, double facteur, exclusion d'adresse, identifiants d'API, sessions d'un compte.
- Jetons délégués (plan MCP, lot 4) : `dotnet/LogiBTP.Authentification/ReglesJetonsDelegues.cs` (`Prefixe`, `Nouveau`, `Echeance`, `Refus`, `RouteAuthPermise`), `ServiceAuthentification.JetonsDelegues.cs` (`EmettreJetonDelegueAsync`, `OuvrirJetonDelegueAsync`, `SessionDelegueeAsync`, `RevoquerJetonDelegueAsync`, `RevoquerDelegationAsync`, `RevoquerJetonsDuCompteAsync` ; `ServiceJetonsDelegues` : contrat `IJetonsDelegues`), entité `JetonDelegueEntite` ; `db/005c_jetons_delegues.sql` (rejouable) : `jeton_delegue` (compte, délégation, empreinte, client, échéance, révoqué le, dernier usage, dernière adresse), événement `JETON_DELEGUE` du journal.
- `db/005_authentification.sql` (rejouable) : `parametre_authentification` (session, verrouillage, mot_de_passe, pseudos_reserves), `compte` (unique sans casse, une personne liée = un compte, SERVICE sans empreinte ni personne), `session_utilisateur` (empreinte du jeton, expiration, persistante, test), `journal_connexion` ; comptes de service `archivage_ged`, `editions_fond` ; `reinitialisation_mdp` (mot de passe oublié : empreinte du jeton, expiration, utilisation), événement `MDP_OUBLI` du journal.

## Routes HTTP (préfixe `/api/auth`)
- Publiques : `POST /oubli` { identifiant }, `POST /reinitialiser` { jeton, nouveau } ; `GET /politique` indique `oubli_courriel`.
- `GET /session` (public : connecté, code, libellé, profil, mot de passe à changer, personne liée, expiration, mode, comptes de test, « Rester connecté » permis), `GET /politique` (public : longueur minimale, mots de passe courants, pseudos réservés), `POST /connexion` { identifiant, mot_de_passe, rester_connecte }, `POST /deconnexion`, `POST /mot-de-passe` { actuel, nouveau }.
- Développement : `GET /test/comptes`, `POST /test/connexion` { identifiant }.
- Lot 3 : `POST /connexion` → session ou { double_facteur, etape, destination } ; `POST /connexion/code` { etape, code } ; `POST /jeton` { identifiant, secret }, `POST /jeton/rafraichir` { rafraichissement } (publiques) ; `GET /sessions` (mes sessions, machines, double facteur choisi), `DELETE /sessions` (les autres), `DELETE /sessions/{id}`, `DELETE /machines/{id}`, `PUT /double-facteur` { actif } ; administrateur : `GET /comptes/{id}` (+ sessions, machines), `DELETE /comptes/{id}/sessions`, `DELETE /comptes/{id}/machines/{machine}`, `POST /comptes-api` { code, libelle, profil, adresses } → { compte, mot_de_passe = secret }, `POST /comptes-api/{id}/secret`, `PUT /comptes-api/{id}/adresses`, `GET /exclusions`, `POST /exclusions/{id}/lever`.
- Usurpation : `POST /usurper` { identifiant, motif } → description de la session (`usurpation` : code, libellé, profil, fin, motif), `POST /usurper/fin`.
- Administrateur : `GET /profils`, `GET /comptes?recherche=&etat=`, `GET /comptes/{id}` (compte, personne, 50 derniers événements du journal), `POST /comptes` { code, type_element, id_element, profil, valide_jusqu_au } → { compte, mot_de_passe }, `PUT /comptes/{id}` { code, profil, valide_jusqu_au, actif }, `POST /comptes/{id}/reinitialiser` → { compte, mot_de_passe }, `POST /comptes/{id}/deverrouiller`, `GET /personne?type=&id=` (personne et son compte), `GET /personnes?recherche=` (personnes autorisées, compte éventuel).
