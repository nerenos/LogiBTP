# Page document du cœur (onglets, grille, entête, transformation) – contexte

Règles de la page document (`pages/document.js`, `editeur-btp.js`, `panneaux-btp.js`, `analyse-*.js`, `documents/`) ; moteur et frais annexes : `src/calcul/CLAUDE.md` ; règles génériques du module Document : `modules/document/CLAUDE.md`.

- Postes de pied : groupes « Postes de pied HT / TTC » toujours affichés (vides : lignes d'accueil, `EditeurDocument.insererPoste`) ; type d'élément `POSTE_PIED` de la bibliothèque (`modules/bibliotheque/db/063`, fiche élément : groupe Poste de pied ; démo RG5, PRORATA, REMISE5, FRAISDOS) inséré dans le pied par code, F3 ou glisser (`AppelBibliotheque.deployerPoste`, `valeursPoste`).
- Page document : panneaux ancrables (`.dock[data-dock-id]` : détail, plan, notifications) répartis par `Disposition` dans trois zones (gauche, droite, bas) ; positions, tailles et visibilité dans le navigateur. Plan du document (`PlanDocument`) : tranches (titres) et pied ; « Aller à » ou « Filtrer » (filtre d'affichage seulement : `EditeurDocument.filtrer`, la saisie et le calcul portent sur tout le document). Notifications (`NotificationsDocument`, dock en bas, masquable : Alt+7) : calcul, contrôles de saisie (`controlesSaisie` : sans unité, coefficients FG / bénéfice < 1, PA et PV à 0, quantité à 0 ; avertissements JS seuls, jamais bloquants), validation, métrés ; filtres par gravité, source et type gardés dans le navigateur ; F8 / Maj+F8, icône de la poignée, clic droit. Onglets : Entête Alt+1, Règlements 2, Lignes 3, Analyse 4, Pièces 5, Suivi 6, Options 8 (modèle, décimales, numérotation, calcul des ouvrages, bibliothèque, étiquettes : `rendreOptions` / `champsOptions`) ; refus de validation : champ hors des lignes en cause encadré avec son onglet et « Aller » (`CHAMPS_ERREUR_DOCUMENT` de `codes.js`). « ⧩ Filtrer la grille » sur les lignes signalées (`filtrerSignalees`), cellule en cause soulignée (`colonnes` des messages, `signalCellule` de la grille) ; légende repliable en bas du plan (présent dans le document seulement). Unité d'une ligne liée à un article : unités de l'article en tête de liste, conversion du prix proposée (`unitesArticle`, `conversionUnite` de `bibliotheque/appel.js`, `EditeurDevisBtp.changerUnite`). Retrait des niveaux de la grille dégressif et plafonné (`--grille-retrait*`). Le pied entier est une tranche virtuelle repliable (`ID_PIED`). Lots du devis de démonstration (jeu de test, `client/src/app/demo.js`) générés par `client/src/app/demo-lots.js` ; l'application ouvre les documents de la base (plus de `/document/demo`).
- Onglet Analyse : calculs dans `client/src/app/analyse-calcul.js` (feuilles, agrégats, éléments regroupés par code et libellé (`elementsAnalyse`, `modificationsElement` : PR écrit par le FG, PV en prix fixe ; `repartirQuantite` : quantité totale (perte et ouvrages parents compris) reventilée au prorata, quantités saisies recalculées, métrés désactivés mais conservés), marges brute = prix client − déboursé et nette = PV remisé sans FA ni prorata − revient, `forcerMontant` ; `rechargementPrix` : prix du jour de la bibliothèque sur les éléments affichés, PA rechargé et coefficients conservés, PV fixe de la bibliothèque repris en PV fixe, PV fixe de la ligne conservé, rapprochement par le code à cocher), interface dans `analyse-coefs.js` (bouton « ⟳ Prix de la bibliothèque », aperçu `apercuPrix`). Les montants sont les vraies valeurs : un montant saisi recalcule les coefficients des feuilles, les plus fortes absorbent l'arrondi, et en dernier recours une ligne d'écart d'arrondi est ajoutée dans la nature (test `client/test/analyse-calcul.test.js`, vérifié après recalcul par le moteur).
- Recherche dans les lignes (`RechercheLignes`, Ctrl+F ou 🔍 dans la page document) : sans filtre, lignes trouvées surlignées (`EditeurDocument.marquer`), passage de résultat en résultat avec dépliage des tranches (`allerA(id, { focus })`). Codes du devis de démonstration : `coderDemo` (`OUV-nnn`, éléments par nature, même libellé = même code).
- Documents, lot 9 des demandes du 25/10/2026 : date de livraison par ligne (`lig_date_livraison`, module Document `019l` ; vide = date de l'entête par `dateLivraisonDefaut`), accusé de réception des commandes (`db/238`, `PUT /api/structure/documents/{id}/arc` même validée, GED catégorie `arc`), date effective `f_date_livraison_ligne` lue par la projection du stock ; lot de demandes de prix : envoi groupé (un courriel par fournisseur, module Mail) et offre retenue dans le comparatif (transformation, autres offres au statut `NON_RETENU`, module Document `019m`).
- Page document : rattachement saisi par code (composant `champRattachement` de `structure/selection.js`, aussi dans les fiches de la structure : double-clic ou F4 = liste de choix), libellé en lien vers la fiche, parents complétés par l'enfant (marché → chantier → affaire et projet) ; variables du document ($$, sans ligne ni métré, évaluées en premier par les moteurs) éditées dans le métré de la ligne SECTION (`variablesDocumentSur` de l'hôte du panneau métré) ; section sans code : numéro du document dans la colonne Code ; actions de la bibliothèque (prix, envoi) dans le détail de la ligne ; onglet Pièces = GED du document (`type_element` = code du type, `id_element` = groupe des indices), pièces jointes à envoyer (`dge_a_envoyer`, option `envoi` de `ExplorateurGed`, module Mail à venir). Paiement direct des intervenants : information dans l'entête ; montants, agréments et déduction par le module Sous-traitance (lot 4).
- Nature des lignes (`lig_nat_id`, colonne Nature de la grille et du détail) : obligatoire sur les lignes de prix (éléments, ouvrages, composantes ; hors écart d'arrondi) pour valider, pas pour enregistrer. Contrôle hors moteurs de calcul (les jeux de cas partagés comparent les codes d'erreur) : `controlesValidation` (`client/src/calcul/controles-btp.js`, affiché par `PanneauxBtp.controlesSupplementaires`) ↔ `SpecialisationBtp.ControlerValidation` (point d'accroche `SpecialisationDocument.ControlerValidation`, appelé par `DocumentService.Valider`). Grille du socle : `classeCellule` / `titreCellule` par colonne.
- Compte comptable et commentaire des lignes (`lig_cpt_code`, `lig_commentaire` du module Document ; colonnes Compte et Commentaire, détail) : sans compte, la ligne affiche en souligné le compte hérité par la règle de ventilation du module Comptabilité (`client/src/app/comptes.js`, `compteLigne`, remplaçable par `definirRegleCompte` : compte de produit ou de charge du tiers de la relation — `per_cli_compte_produit`, `per_fou_compte_charge`, `per_st_compte_charge`, `db/247`, jamais son compte auxiliaire —, clés de ventilation, défaut du type) ; libellés : plan de comptes minimal `compte_comptable` (`db/166`, `GET /api/comptes-comptables`).
- Colonnes de la grille des lignes déplaçables (glisser l'entête) et redimensionnables (bordure droite, double-clic : automatique) : `GrilleArbre` (option `actions.colonnesModifiees`, `colonne.largeur`) → `EditeurDocument.modifierDisposition` → `GestionVuesDocument` : disposition gardée dans le navigateur par vue (`dispositionColonnes`, `fusionnerDisposition`) ; enregistrer la vue (dialogue des colonnes) écrit ordre et largeurs dans `vue_document` (`colonnes: [{ cle, largeur }]`).
- Transformation d'un document : fenêtre de choix commune (`client/src/app/documents/transformation.js` : cibles regroupées par étape, ventes puis achats, tout le reliquat), page document et bouton « ⇢ Transformer » des listes (actions supplémentaires `autres` de `actionsElements`, avec `actif(lignes)`). `Disposition` (module Document) cherche ses éléments dans `racine` (conteneur de la page) : l'ancienne page est encore dans le document pendant l'ouverture de la suivante.
- Entête des documents : TVA par défaut du document (`ent_tva_id`, module Document `019o` : nouvelles lignes hors d'un titre à taux, « Appliquer à toutes les lignes » ; le taux d'un titre modifié s'impose à toute sa tranche), notre référence, référence externe, validité en jours (défaut `tyd_validite_jours` du type) et fin de validité calculée à la validation (`ent_date_validite`, serveur) dans le module Document ; rédacteur (`ent_redacteur_id`, individu de notre société, combo saisissable) dans le cœur. L'ancienne propriété `duree_validite` est remplacée par `ent_validite_jours`.
