# Client LogiBTP (cœur, application web Vite)

- Détail à lire avant de toucher une partie (inventaire des fichiers, modèle de données, points de spécialisation, routes) : [CLIENT.md](../documentation/modules/CLIENT.md).
- Règles par partie, dans le `CLAUDE.md` de leur dossier : page document et ses onglets (`src/app/documents/`), moteur de devis et frais annexes (`src/calcul/`), structure, marchés et révision des prix (`src/app/structure/`), bibliothèque (`src/app/bibliotheque/`), ressources (`src/app/ressources/`), terrain (`src/app/terrain/`), import (`src/app/import/`), saisie hors ligne et fusion (`src/app/hors-ligne/`), application installable (`src/pwa/`).

## Rôle
- Application web du cœur (`logibtp-client`, workspace npm) : spécialise les paquets JS des modules (`@logibtp/socle`, `metre`, `document`, `liste`, `fiche`, `ged`, `navigation`, `bibliotheque`, `graphe`, `annuaire`, `entreprises-fr`, `import`) ; aucun module ne dépend du client.
- En ligne : API C# par `/api` (proxy Vite vers `http://localhost:5080`, ou `LOGIBTP_API` pour une autre instance ; `Host` conservé pour choisir la société). L'application exige l'API (plus de démo hors ligne) : injoignable au démarrage (`api.disponible()` sur `/api/sante`), écran « Serveur injoignable » recontrôlé toutes les 15 s puis rechargement (`Application.#attendreApi`) ; fournisseurs des modules toujours ceux de l'API (`services()`).

## Repères
- Inventaire de `src/` par module et par lot (pages, routes, fichiers, fonctions) : [CLIENT.md](../documentation/modules/CLIENT.md).
- Pages dans `src/app/pages`, déclarées dans `pages/index.js` (`ROUTES`) ; sans session en ligne, seule `/connexion` s'ouvre (la borne `/borne` n'a pas de session).
- `src/main.js` attend `chargerPersonnalisation()` avant d'importer l'application ; aucun script en ligne dans `index.html` (CSP de `vite.config.js`, alignée avec `ClientWeb.Csp` du socle).
- Menus du bandeau et raccourcis : `src/app/navigation/menus.js` ; widgets : `navigation/widgets.js`.
- Parité avec le serveur : `calcul/moteur-btp.js` ↔ `MoteurDevisBtp.cs` (colonnes de `calcul/colonnes-btp.js` alignées sur les entités), `calcul/controles-btp.js` ↔ `SpecialisationBtp.ControlerValidation`, `frais-annexes.js` (`figerVentilation`) ↔ `SpecialisationBtp.FigerVentilation`, `ressources/*.js` ↔ `Regles*.cs` du cœur (jeux `tests/ressources`), `structure/adresses.js` ↔ `AdressesDocument`, `controlerIntervenants` ↔ `Intervenants.Controler`, `synchroniserSalarie` ↔ `SalariesAnnuaire.Synchroniser`, `completerRattachement` ↔ `PUT /api/structure/documents/{id}/rattachement`, règles de `fiches.js` / `fiche-annuaire.js` ↔ `SpecialisationFicheBtp`.

## Règles d'interface (valent pour tout le projet)
- Pages : une page dérive de `PageBase` (`ouvrir`, titre, `modifiee`, `quitter`, `reprendre`, `masquer`, `fermer`, `urlCourante` ; `liberer` n'existe que dans les pages document et fiche). Toute ouverture d'écran passe par `app.naviguer(url, { nouvelleFenetre })`, jamais par un panneau superposé ; fermer une fiche ou un document passe par `app.fermerPage(defaut)` (fenêtre séparée : la fenêtre se ferme, sinon retour).
- Fenêtres d'interaction : élément `<dialog>` (`confirmer` / `alerter` / `saisir` / `ouvrirModale` de `socle/js/src/ui/dialogue.js`, avec `await`), jamais `confirm()`, `alert()`, `prompt()` ni fond superposé en `div`.
- Messages : erreurs et avertissements dans la fenêtre à décompte du socle (`notifier`, par `app.message` / `app.erreur(e, { libelle, aller })` : détails d'une erreur de l'API listés avec « Aller » ; fiches : `allerAuChamp`), succès dans le bandeau (historique 🕘) ; infobulles du thème (`activerInfobulles`, les `title` restent) ; barres d'outils en groupes séparés (`.barre-outils` > `.groupe-outils`).
- Listes de choix (combos) : la saisie filtre la liste ou sélectionne directement l'option (libellé ou code) ; la flèche (clic dans le champ, F4, Alt+↓ ou ↓) rouvre la liste même en saisie, après un choix ; jamais de `<select>` simple (les `<select>` restants s'affichent en combos par `activerCombos` du socle, appelé au démarrage du client) : hors grille, `creerCombo` du socle (`socle/js/src/ui/combo.js`, utilisé par la saisie des listes, les champs `liste` des fiches et le rédacteur). Grilles : `editeur: 'select'` = combo du socle (`ListeDeroulante` en mode strict : libellé affiché, valeur = identifiant, `resoudre()` ; un texte qui ne désigne aucune option reste en saisie).
- Dates : champ texte à saisie abrégée du socle (`activerDates`, `completerDate` : « 15 » → le 15 du mois en cours, « 16/05 » → l'année en cours, « 15/05/23 » → 2023), `value` en ISO comme l'input natif ; jamais de lecture de date maison (grille : `lireDateSaisie` s'appuie dessus). Évolutions d'ergonomie à venir : [ANALYSE-ERGONOMIE.md](../documentation/conception/ANALYSE-ERGONOMIE.md).
- Raccourcis clavier personnalisables (`/parametres/raccourcis`) : chaque fonction est déclarée dans un groupe (`declarerRaccourcis` du socle ; grille : `raccourcis.json`, application et page document : `src/app/raccourcis.js` ; fiches, listes et GED : groupes `fiche`, `liste`, `ged` de leurs modules, complétés par l'hôte) et lue par `actionDe(e, groupe)`, jamais par un test de touche en dur. Clic droit (`ouvrirMenuContextuel`) : menu court, aide-mémoire des raccourcis (touches par `libelleRaccourci` : grille des lignes, listes, fiches, explorateur GED, entête du document) ; tout reste accessible sans lui ; le menu du navigateur reste sur les champs de saisie.
- Bandeau : logo à gauche (accueil), libellés courts `court` des menus quand la place manque, sous-menus (`sousMenu`), paramètres de chaque module dans son menu ; disposition au choix (préférence `menu` du navigateur, Paramètres › Affichage ou menu Paramètres › Position du menu) : en haut (défaut), à gauche ou à droite sur toute la hauteur (menus dépliés au clic, tactile, largeur réglable, masquable, masquage automatique, informations en bas).
- Préférences d'affichage dans le `localStorage` du navigateur, jamais en base, sauf celles qui suivent le compte d'un poste à l'autre : accueil (raccourcis et widgets) par `preferencesCompte` (`src/app/preferences-compte.js`, même interface que `Preferences`, valeur du navigateur reprise une fois), table `preference_compte` (`db/264`), `GET|PUT /api/preferences/{cle}` du compte connecté (`Btp/PreferencesCompte.cs`) ; raccourcis et widgets filtrés par les droits (`droit` des menus et des widgets). Préférences du navigateur comprises : densité confortable par défaut ou compacte (`html[data-densite]`, variables `--taille-texte`, `--grille-hauteur-ligne`, `--cellule-marge` du socle), raccourcis clavier personnalisés, remises des lignes en coefficient ou en % (préférence `remises`, le document garde le coefficient).
- Présentation : vues de paramétrage en tableaux à la largeur de leur contenu, calés à gauche (`.page-parametres table`, classes `pleine-largeur` et `tableau-compact` pour l'exception) ; ligne de titre d'une page `.entete-page` (titre et commandes sur une ligne) ; tableau de données compact `.tableau-compact` (séparations atténuées, en-têtes figés, titres et cases sur deux lignes ; champs et combos remplissant leur cellule, largeur minimale selon l'attribut `size`, boutons dans leur propre colonne `.cellule-boutons`). Référence de présentation des pages de données : toutes les pages du module Pointage (synthèse, saisie, export, paramètres, bornes, groupes), avec le panneau latéral réductible (`panneau-lateral.js`) et les actions en icônes.

## Spécialisation des modules
- **Document** : `EditeurDevisBtp`/`ReglesBtp`/`PressePapiersBtp` (`editeur-btp.js`), `PanneauxBtp` (`panneaux-btp.js`, `controlesSupplementaires`), `MoteurDevisBtp` (`calcul/moteur-btp.js`), colonnes `calcul/colonnes-btp.js`, vues `vues-document.js`, page `pages/document.js`, transformation `documents/`.
- **Métré** : `DictionnaireBtp extends DictionnaireMetre` (groupes Ligne — colonnes lisibles avant la quantité vendue, dont les données techniques — et Entête `{{document.ent_…}}`), `PanneauMetre` dans la page document et la fiche élément ; moteur via `Portees`, `evaluerScriptMetre` (métrés en script : `evaluerScript`, `resolveurScript`, `ecrireScript`, `libelleEcrit`, `sourceLibelle` ; résultat `scripts`).
- **Liste** : `listes.js` + `vues-liste.js` ; `pages/liste.js` (`ListeDonnees`, options `filtresVue` → `FiltreRattachement`, `actionsElements`, `glisser`).
- **Fiche** : `fiches/*` (classes dérivées de `FicheBase` via `FicheLogiBTP`), `pages/fiche.js`.
- **GED** : `ged/ged.js`, `ged/arborescence.js` (`ArborescenceBtp extends ArborescenceGed`), `ExplorateurGed` dans `pages/ged.js` (racine : documents sans élément, Affaires, Projets), `pages/fiche.js` (racine : la fiche), `pages/document.js` (racine : le document, enfants par `structure.descendants`).
- **Bibliothèque** : `bibliotheque/*`, `fiche-element.js`, `pages/parametres-bibliotheque.js`, `PanneauArbres` dans `pages/liste.js`.
- **Annuaire / Entreprises FR** : `annuaire/*`, `fiche-annuaire.js`, `pages/graphe.js` (`VueGrapheAnnuaire`), `pages/parametres-annuaire.js`.
- **Graphe** : `structure/graphe-structure.js` (`VueGrapheStructure extends VueGraphe`). **Navigation** : `application.js`, `navigation/*`, pages. **Import** : `import/*`, `pages/import-optim.js`.

## Conventions et pièges
- Montants en decimal.js (`D`, `S`, `arrondir` du socle), jamais `Number` ; toute règle de `moteur-btp.js` se reporte dans `src/LogiBTP.Calcul/MoteurDevisBtp.cs` avec un cas dans `tests/cas`.
- Colonnes de `colonnes-btp.js` alignées sur `DocumentBtp` / `DocumentLigneBtp` (test xUnit `Colonnes_btp_alignees_avec_le_moteur_js`).
- `vues-liste.js`, `fiches/definitions.js`, `vues-document.js`, `bibliotheque/donnees.js`, `annuaire/donnees.js`, `structure/donnees.js`, `editions/modeles.js` : source unique du SQL généré → modifier la source puis `npm run generer-vues-liste --workspace client` (`db/CLAUDE.md`), jamais le SQL.

## Commandes
- `npm install` (racine) ; `npm test` (tous workspaces) ou `npm test --workspace client` ; `npm run dev` (Vite, port 5173).
- `npm run exporter-resultats` puis `dotnet test LogiBTP.slnx` : parité complète des moteurs.
- Démo : API `dotnet run --no-build --project src\LogiBTP.Api --launch-profile http` (5080), base PostgreSQL sur 5433 ; société « demo » par http://demo.localhost:5173.
- Documents de démonstration (devis, commandes, situations, livraisons, factures, achats, avoirs, avec transformations) : `node client/scripts/generer-documents-demo.mjs <host> <id d'un devis de la base>` par l'API (localhost 2, demo.localhost 1) ; puis modules Exécution, Planning, Pointage, CRM et notifications : `node client/scripts/generer-modules-demo.mjs [host] [--force]` (défaut demo.localhost ; dates relatives à aujourd'hui ; une seule fois sauf `--force`). Transformation : les sous-totaux de pied (racine) et les bases des lignes de pied sont conservés.
