# Module CRM – contexte

## Rôle
- Suivi de la relation et de l'information autour des affaires ([analyse](../../documentation/conception/ANALYSE-MODULE-CRM.md), décisions C1 à C30) : notes (actions, messages, tâches), rappels, demandes (pré-dossiers de veille), suivi des validations des plans, bordereaux de diffusion, fil d'actualité.
- Facultatif, activé par société (`module_societe`, code `crm`) : désactivé, menus et onglets masqués, routes refusées (409 `MODULE_INACTIF`), données conservées.
- Ne connaît pas l'application : un élément rattaché est un couple (`type_element`, `id_element`) comme dans la GED ; individus et services sont des identifiants décrits par la spécialisation.

## Dépendances
- Dépend de : `@logibtp/socle` (JS), `LogiBTP.Socle` / `LogiBTP.Socle.Web` (`Utilisateur`, `ExceptionMetier`), EF Core Npgsql, HtmlSanitizer (même liste blanche que `htmlSur` et le module Document, sans dépendre de lui). Jamais du cœur ni d'un autre module.
- Utilisé par : cœur (`SpecialisationCrmBtp` : éléments tiers, contacts, projets, affaires, chantiers, marchés, documents — groupe d'indices —, individu de l'utilisateur par `ind_utilisateur`, services de `db/193` ; `db/194` : élément GED `crm_note`, catégorie `crm` ; écrans `client/src/app/crm/*` et `pages/crm*.js`).

## Règles
- Note : nature ACTION / MESSAGE / TACHE, état A_FAIRE / EN_COURS / TERMINE / MEMO / ANNULEE (clos : TERMINE, MEMO, ANNULEE). Tâche : responsable ou service, et échéance ; message : un destinataire sauf une réponse (`not_parent_id`) ; privée ou RGPD : jamais dans le fil (`not_dans_fil`, décoché par défaut).
- Responsable nul avec un service : note « à prendre », visible de tous les membres du service ; « Prendre » = devenir responsable (état EN_COURS si À faire) ; « Rendre au service » ; tout changement tracé (historique : CREATION, ETAT, RESPONSABLE, SERVICE, ECHEANCE).
- Lecture : tout le monde voit les notes ; note privée masquée sauf auteur, responsable, destinataires ; note RGPD masquée sauf l'auteur. Levée du masquage (`?reveler=true`) : droit SUPERVISER (privée) ou RGPD, consultation journalisée (`crm_consultation`), visible de l'auteur et de l'administrateur. La recherche ignore le contenu des notes protégées.
- Modification : administrateur, auteur, responsable, destinataire, membre du service d'une note à prendre ; contrôle des modifications concurrentes par `maj_le` (409 `NOTE_MODIFIEE`). Suppression : l'auteur tant que personne d'autre n'a lu, modifié ni répondu (sinon 409 `NOTE_UTILISEE` : l'annuler), l'administrateur toujours.
- Rappels : DATE (date et heure) vert avant, rouge ensuite ; AVANT (délai en jours avant l'échéance de la note, nul = seuil orange) : couleur par les seuils globaux (rouge ≤ seuil rouge, échéance dépassée comprise ; orange ≤ seuil orange ; sinon vert), visible dans « Mes rappels » et le widget dès l'échéance moins le délai ; note close ou rappel traité : inactif. Contrôles : `RAPPEL_TYPE`, `RAPPEL_DATE`, `RAPPEL_DELAI`, `RAPPEL_ECHEANCE` (AVANT sans échéance), `RAPPEL_CLOS`. Pour un autre individu : il faut pouvoir modifier la note ; « Mes rappels » = pour mon individu, ou créés par moi sans individu. Seuils : administrateur (`SEUILS_RAPPEL` : rouge ≥ 0, orange ≥ rouge). Pas de tâche de fond ni de notification poussée (second temps).
- Demandes : pré-dossiers de veille avant le projet ; VEILLE → A_ETUDIER → EN_COURS → TRANSFORMEE (seulement par « Créer le projet » : `CreerProjetAsync` du cœur, projet au code du chrono des projets (PRJ-AAAA-NNN par défaut) repris de l'objet, du tiers, du montant, du responsable et de la description ; les notes de la demande sont aussi rattachées au projet) ou SANS_SUITE (motif PERDUE / NON_RETENUE / ABANDONNEE). Prise en charge par un service comme les notes. Notes, tâches et courriels d'une demande : notes rattachées à l'élément `crm_demande` (onglet Suivi de la page). Suppression : l'auteur tant qu'il n'y a ni note ni projet, sinon l'administrateur. Pas de confidentialité propre.
- Validations : statut du dernier indice (À diffuser sans date, Sans visa, En attente, Refusé dès un refus, Bon pour exécution si tous les visas sont reçus sans refus avec au moins une acceptation), indice en vigueur = dernier indice bon pour exécution, visas manquants et en retard (attendus avant aujourd'hui), bloquant tant que le dernier indice n'est pas bon pour exécution. Indice vide à la création : suivant du dernier (A → B, Z → AA), ou indice vide `''` si le plan n'en a pas (le premier, avant A). Fichiers d'un indice : un répertoire de la GED par indice sous l'élément `crm_plan` (« Indice A », « Indice vide »), retenu sur l'indice (`pin_rge_id`), créé par l'écran ; un nouveau plan reçoit ses fichiers dès la création (repère, nom et indice lus dans le nom du premier fichier selon le format global `format_plan`). Suppression d'un plan ou d'un indice diffusé ou visé : administrateur. Visa reçu : remis en attente (statut vide) ou supprimé par l'administrateur.
- Bordereau : pièces = indices de plans (ou documents de la GED) ; un indice sans date prend celle du bordereau ; un destinataire qui vise reçoit un visa attendu par indice (date + délai) et, si l'utilisateur est relié à un individu, une tâche de retour (rattachée au bordereau, au tiers et à l'élément) terminée quand tous ses visas sont reçus, rouverte si l'un repasse en attente. Impression : page `/crm/diffusion/:id` (feuille d'impression du navigateur ; modèle du module Édition plus tard).
- Fil d'actualité : ne stocke rien d'autre que les événements ; réunit les notes cochées « Dans le fil » (jamais privées ni RGPD, sans les réponses), les documents et photos de la GED des éléments du périmètre (fournis par la spécialisation : internes, ni supprimés ni archivés ; image = type MIME image/*), les pièces des notes et les événements ; périmètre agrégé vers le haut (`PerimetreAsync` : projet, affaire, chantier, marché → chantiers, marchés, documents par groupe d'indices ; plus les plans, bordereaux et demandes transformées rattachés) ; global (sans élément) : notes et événements seulement. Chargement par lots : `avant` = date du dernier élément reçu (`suivant` nul : fin) ; photos déposées ensemble (même élément, même auteur, moins de 10 minutes) regroupées ; le client montre trois vignettes et le reste en nombre, les documents s'ouvrent à la demande. Pas de miniatures (second temps).
- Conservation : jusqu'à l'archivage (module Archivage à venir, `not_archivee_le`) ou la suppression du tiers.

## Routes HTTP (préfixe `/api/crm`)
- `GET /contexte` (utilisateur, individu, services, droits, types d'éléments, services, types de notes), `POST /elements` ([{ type, id }] → libellé, page, icône).
- `GET|PUT /types-notes` (PUT : administrateur ; un type retiré utilisé est désactivé).
- `GET /notes?vue=mes|a_prendre|recues|creees|toutes&type_element=&id_element=&nature=&etat=ouvertes|<code>&srv=&recherche=&page=&taille=` (notes racines, non archivées, triées par échéance puis création).
- `GET /fil?type_element=&id_element=&avant=&taille=&genres=NOTE,DOCUMENT,PHOTO,EVENEMENT` ([{ genre NOTE | DOCUMENT | PHOTOS | EVENEMENT, quand, par, titre, texte, element, url, note_id, nb_reponses, pieces }], suivant).
- `GET|PUT /statuts-visa`, `GET /plans?type_element=&id_element=&recherche=`, `GET|PUT|DELETE /plans/{id}`, `POST /plans`, `POST /plans/{id}/indices`, `PUT|DELETE /indices/{id}`, `POST /indices/{id}/visas`, `PUT|DELETE /visas/{id}`, `GET /diffusions?type_element=&id_element=`, `GET /diffusions/{id}`, `POST /diffusions`.
- `GET /rechercher?type=&texte=` (demandes, plans, documents par numéro ou objet), `GET /demandes?vue=mes|a_prendre|creees|toutes&etat=ouvertes|<code>&recherche=&tiers=&page=&taille=`, `GET|PUT|DELETE /demandes/{id}`, `POST /demandes`, `POST /demandes/{id}/prendre|rendre|projet`.
- `GET|PUT /parametres` (seuils, `format_plan` : nul au PUT = inchangé, contrôlé `FORMAT_PLAN` ; PUT administrateur), `GET /rappels?tous=` (mes rappels actifs ; visibles seulement par défaut), `POST /notes/{id}/rappels`, `PUT|DELETE /rappels/{id}`, `POST /rappels/{id}/traiter` ; le détail d'une note porte ses rappels.
- `GET /notes/{id}?reveler=`, `POST /notes`, `PUT /notes/{id}`, `DELETE /notes/{id}`, `POST /notes/{id}/prendre|rendre|lue`.
