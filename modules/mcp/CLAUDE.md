# Module MCP – contexte

- Plan par lots : [mcp.md](../../documentation/conception/plans/mcp.md) ; analyse : [ANALYSE-MODULE-MCP.md](../../documentation/conception/ANALYSE-MODULE-MCP.md) (§ 4 délégation, § 5 garde-fous et interdits, § 10.1 propositions).

## Rôle
- Agents IA connectés à l'application (point `/mcp`) au nom d'un utilisateur, dans la limite d'une **délégation** : plafond (modèle), garde-fous, interdits absolus, échéance, quotas. Lot 2 : règles (répliquées JS ↔ C#) ; lot 5 : `LogiBTP.Mcp.Web` (point `/mcp`, délégations, plafond, appel interne, journal) ; lot 10 : file des propositions (action préparée par l'agent, exécutée par l'humain qui l'accepte, sous son identité) ; lot 11 : écrans (`js/ui`) ; lot 12 : serveur d'autorisation OAuth 2.1 (clients distants : claude.ai) ; lot 13 : recettes (prompts MCP) et « Demander à l'agent ».
- Sans métier : ne connaît ni les nœuds du cœur ni ses routes ; le cœur fournit le catalogue des nœuds, les nœuds retenus par garde-fou (TIERS, SALARIES, PAIE, CRM_NOTES, COUTS…) et des interdits supplémentaires (spécialisation, lots 5 et 6).

## Dépendances
- JS `@logibtp/mcp` → `@logibtp/socle` (codes `ACTION_DROIT`, `PORTEE_DROIT`, `GARDE_FOU`, `MODELE_PLAFOND`, `ajouterJours`). .NET : `LogiBTP.Mcp` → `LogiBTP.Socle` ; `LogiBTP.Mcp.Web` → `LogiBTP.Mcp`, `Socle.Web`, `Socle.Donnees`, EF Core Npgsql, `ModelContextProtocol.AspNetCore` 1.4.2 (SDK officiel, Streamable HTTP). Authentification et Droits seulement par les contrats du socle (`IJetonsDelegues`, `IDroits` ; `IPlafondAgent` implémenté ici). Jamais du cœur ni d'un autre module : la forme des droits d'un profil (`{ total, lignes: { nœud: { ACTION: PORTÉE } } }`, héritage du plus proche ancêtre) et les alias d'actions sont repris du module Droits **sans l'importer**.

## Repères
- `js/src/delegation.js` ↔ `dotnet/LogiBTP.Mcp/ReglesDelegation.cs` (jeu `tests/cas/01_delegation.json`) :
  - `actionsModele` / `ActionsModele` : LECTURE → CONSULTER ; PREPARATION → CONSULTER, CREER, MODIFIER ; COMME_MOI, SUR_MESURE → null (non bornés par le modèle).
  - `gardesFousActifs` / `GardesFousActifs` : tous les `GARDE_FOU` sauf ceux levables pour le profil **et** levés par la délégation.
  - `estInterdit` / `EstInterdit` : nœuds `administration`, `connexions`, `mail` (préfixes), `parametres` hors CONSULTER, actions FORCER, USURPER, PARAMETRER, DEVERROUILLER (et leurs alias DEVALIDER, DEBLOQUER), plus les interdits de la spécialisation (code d'action ou préfixe de nœud).
  - `droitsEffectifs` / `DroitsEffectifs(profil, plafond, gardesFous actifs, options { catalogue, noeuds, interdits })` : intersection par nœud et action, portée la plus étroite (et ≤ `plafond.portee`, TOUT par défaut, inconnue → SOI) ; SUR_MESURE : `plafond.actions` `{ nœud: [actions] }` avec héritage ; VALIDATION retire VALIDER, SUPPRIMER, DEVALIDER ; RGPD retire RGPD, CONFIDENTIEL ; nœud retenu par un garde-fou actif : **toutes** ses actions retirées (sans lecture, pas d'écriture). Profil total : développé par le catalogue, COMME_MOI → rien, SUR_MESURE borné à la préparation. Résultat sous la forme des droits d'un profil, lignes redondantes retirées.
  - `autoriseAgent` / `AutoriseAgent` (sur les droits effectifs), `controlerDelegation` / `ControlerDelegation` (`ERREUR_MCP` : modèle inconnu ou non permis, `MCP_ADMIN_COMME_MOI`, échéance 1..min(maximum du profil, 90), garde-fou levé non levable), `echeanceDelegation` / `EcheanceDelegation` (30 j par défaut, bornée), `appliquerQuota` / `AppliquerQuota` (200 par appel, 5 000 par jour, alerte 80 % ; `MCP_QUOTA_JOUR`), `classerOutil` / `ClasserOutil` (`CLASSE_OUTIL` : INTERDIT, LECTURE, BROUILLON, PROPOSITION : action retenue seulement par ENVOI ou VALIDATION que le délégant pourrait faire, jamais pour un plafond LECTURE ni un nœud retenu).
- Constantes `ECHEANCE_DEFAUT`, `ECHEANCE_MAX`, `QUOTA_APPEL`, `QUOTA_JOUR`, `ALERTE_QUOTA`, `NOEUDS_INTERDITS`, `NOEUDS_LECTURE_SEULE`, `ACTIONS_INTERDITES` : parité vérifiée par `CodesTests`.
- `js/src/propositions.js` ↔ `dotnet/LogiBTP.Mcp/ReglesPropositions.cs` (jeu `tests/cas/02_propositions.json`) : `echeanceProposition` / `EcheanceProposition` (7 j par défaut, 1 à 30 : `ECHEANCE_PROPOSITION`, `ECHEANCE_PROPOSITION_MAX`), `etatProposition` / `EtatProposition` (en attente à l'échéance → ECHUE), `controlerDecision` / `ControlerDecision` (agent → `AGENT_INTERDIT` seul ; usurpation `MCP_USURPATION` ; décision inconnue ; `MCP_PROPOSITION_ECHUE` / `MCP_PROPOSITION_CLOSE` ; refus sans motif `MCP_MOTIF_REQUIS`).
- Codes `js/src/codes.js` ↔ `Codes.cs` : `CLASSE_OUTIL`, `ERREUR_MCP` (lot 12 : `MCP_OAUTH_DEMANDE`, `MCP_OAUTH_CLIENT`, `MCP_OAUTH_REDIRECTION`, `MCP_OAUTH_REJEU`), `STATUT_APPEL_AGENT`, `ETAT_PROPOSITION` (EN_ATTENTE, ACCEPTEE, REFUSEE, ANNULEE, ECHUE), `DECISION_PROPOSITION` (ACCEPTER, CORRIGER, REFUSER) (parité par `CodesTests`, `Constantes.Ecarts`). Codes communs (`GARDE_FOU`, `MODELE_PLAFOND`, `ORIGINE_ECRITURE`, `ERREUR_AGENT`) et contrats `IPlafondAgent`, `IJetonsDelegues` : socle (`Socle.Web/Agents.cs`).

## Point /mcp et gestion (lot 5, `dotnet/LogiBTP.Mcp.Web`)
- `db/099u_mcp.sql` (rejouable, manifeste) : `mcp_delegation` (`mde_code` opaque = `jeton_delegue.jde_delegation`, compte, modèle, `mde_noeuds` JSONB sur mesure, portée, `mde_leves`, client, échéance exclue, premier usage, révocation), `mcp_levee_profil` (levables, modèles permis, échéance max, quotas ; sans ligne : rien de levable, défauts), `agent_journal` (§ 9 : paramètres résumés, routes et statut, éléments lus / écrits, garde-fous et clés retirées, statut `STATUT_APPEL_AGENT`, durée), `mcp_compteur` (éléments lus par délégation et par jour).
- `SpecialisationMcp` (méthode patron) : `Noeud` (« agents » : nœud des routes de gestion, toujours interdit à l'agent), `Outils` (`OutilMcp(Nom, Description = clé du dictionnaire, Schema, Methode, Route /api avec {param}, Noeud, Action, Classe)` + `Envoi`, `ClesSensibles` par garde-fou, `ClesNonFiables`, `ParametreLimite`, `CleListe`, `TypeElement`, `CleIdentifiant`), `NoeudsRetenus`, `Interdits`, `ClesSensibles`, `ClesNonFiables`, `Textes` (`Dictionnaire` des descriptions) ; lot 6 : `Module` (code du module facultatif qui active `/mcp` : inactif → 403 `MCP_MODULE_INACTIF`, et `PlafondMcp` sans plafond), `Adresse(outil, élément)` (adresse relative rendue absolue sous la clé `adresse` avec l'origine de la requête MCP, `ServiceMcp.Absolue`), `OutilMcp.LimiteMax` (pagination bornée même sans VOLUME). Arguments non déclarés dans `properties` du schéma : ignorés par `ServiceMcp.Requete`. Outil LECTURE (même en POST) : journalisé en lecture, jamais dans la liste blanche.
- `PlafondMcp` = `IPlafondAgent` (scoped) : délégation active, modèle, nœuds sur mesure, portée, garde-fous actifs (`GardesFousActifs` : levables du profil ∩ levés), liste blanche = routes d'écriture des outils (jamais `/api/mcp`, `/api/auth`, `/api/droits`), interdits = spécialisation + `Noeud` + nœuds retenus des garde-fous actifs ; cache 30 s par base, vidé par `PlafondMcp.Oublier` (révocation, levées). Contrat élargi : `PlafondAsync(délégation, profil)`.
- `ServiceMcp` : `OuvrirAsync` (Bearer → `IJetonsDelegues.OuvrirAsync` → délégation active du même compte, sinon 401 `MCP_JETON_REQUIS` + `WWW-Authenticate: Bearer`), outils exposés = classés LECTURE ou BROUILLON par `ClasserOutil` (droits du profil lus par `IDroits` pour l'humain, sans IDroits : rien), et outils déclarés PROPOSITION dès que leur nœud n'est pas INTERDIT et que le plafond n'est pas LECTURE (un outil d'écriture que `ClasserOutil` range en PROPOSITION reste refusé, `MCP_OUTIL_INTERDIT`) ; appel : quota VOLUME (`AppliquerQuota` : jour épuisé → `MCP_QUOTA_JOUR`, limite bornée, liste tronquée), `ServiceMcp.Requete` (gabarit, requête ou corps), `IAppelInterne`, `FiltreSensible` (clés retirées à toute profondeur, contenus libres en `{ "contenu_non_fiable": … }`), enveloppe `{ donnees, tronque?, cles_retirees? }`, compteur, journal de chaque appel (refus compris).
- Outils composés (lot 7) : `OutilMcp.Routes` (routes appelées en plus de `Route`) et `Execution(ExecutionOutil, ct)` ; `ExecutionOutil` : `Arguments` déclarés, `GardesFous` actifs, `EnvoyerAsync` borné aux routes de l'outil (`RouteOutil.Couvre` : méthode et gabarit segment par segment ; autre route : `RouteNonDeclareeException` → 403 `MCP_ROUTE_NON_DECLAREE`), `Appels` au journal ; la réponse suit le chemin commun (filtre, adresse, journal). Liste blanche du plafond : `PlafondMcp.RoutesEcriture` (routes d'écriture de tous les outils d'écriture, composés compris).
- `AppelInterneHttp` (`IAppelInterne`, substituable) : adresse locale de Kestrel (`IServerAddressesFeature`, HTTP d'abord ; redirection vers HTTPS de l'installation : bascule une fois pour toutes sur l'adresse HTTPS locale), URL à l'hôte de la requête MCP, connexion au port local, `Host` et `Authorization` du jeton délégué, sans redirection suivie.
- `Extensions` : `AddModuleMcp<T>(options)` (SDK : `AddMcpServer().WithHttpTransport(Stateless)`, `WithListToolsHandler` / `WithCallToolHandler` dynamiques), `MapPointMcp()` (`/mcp` ; refus de démarrer si `Authentification:Mode=EnTetes` ou sans `IJetonsDelegues`), `MapModuleMcp()` sous `/api/mcp` : `GET|POST /delegations` (les miennes ; `?toutes=true` administrateur ; création → secret rendu une fois, `ReglesDelegation.ControlerDelegation`, 422 code `ERREUR_MCP`), `POST /delegations/{code}/revoquer` (jetons révoqués par `IJetonsDelegues.RevoquerDelegationAsync`), `GET /delegations/choix` (lot 11 : `ChoixDelegation` du profil — modèles permis, jamais COMME_MOI pour un profil total, garde-fous, levables, échéance par défaut et maximale, portées), `GET /parametres`, `PUT /parametres/{profil}` (administrateur), `GET /journal` (le mien ; `?tous=true` administrateur ; `delegation`, `du`, `au`, `limite`). Agent ou usurpation : 403 (`AGENT_INTERDIT`, `MCP_USURPATION`).
- File des propositions (lot 10) : `db/099v_mcp_propositions.sql` (rejouable, manifeste) `mcp_proposition` (`mpr_action` = exécuteur, `mpr_noeud` / `mpr_droit` exigés de l'humain, cible, `mpr_contenu` corrigeable, avertissements, `mpr_echeance` exclue, état, correction, décision, motif, `mpr_resultat`) ; `agent_journal.ajo_proposition`, `ajo_humain`. Dépôt : outil composé → `ExecutionOutil.Proposer(PropositionPreparee(Action, Noeud, Droit, Libelle, Contenu, CibleType, CibleId, Avertissements, Envoi, Jours))` ; outil de classe PROPOSITION : `ExecutionOutil` en lecture seule (non-GET → `MCP_ROUTE_NON_DECLAREE`), jamais dans `PlafondMcp.RoutesEcriture` ; `ServiceMcp` refuse un exécuteur inconnu (`MCP_EXECUTEUR_INCONNU`), un plafond LECTURE ou une action proposée que `ClasserOutil` (nœud et droit exigés, ENVOI, droits du délégant sur ce nœud) classe INTERDIT (`MCP_OUTIL_INTERDIT`), puis enregistre et rend `proposition { id, action, etat, echeance, adresse }` (`SpecialisationMcp.AdresseProposition`, absolue). Exécution : `SpecialisationMcp.Executeurs` (`ExecuteurProposition(Action, Executer(ExecutionProposition, ct) → JsonObject avec « identifiants »)` + `Controler` du contenu corrigé, `TypeElement`) ; `ExecutionProposition` : cible, contenu, `Humain` (utilisateur de la requête d'acceptation), `Http`, `Services`. `ServicePropositions` + routes `/api/mcp/propositions` : `GET ?vue=miennes|a_valider|toutes&etat&limite`, `GET /{id}`, `PUT /{id}/contenu` { contenu }, `POST /{id}/refuser` { motif }, `POST /{id}/accepter` ; humain seulement (`ExigerHumain`), visible du délégant, de l'administrateur ou de qui a le droit exigé (sinon 404) ; décision contrôlée par `ControlerDecision` puis droit exigé (`IDroits.AutoriseAsync`, sinon 403 `ACCES_REFUSE`) ; acceptation : passage à ACCEPTEE (une seule fois) et exécuteur dans `db.Unite().ExecuterAsync` (tout ou rien, pas de `EnTransaction`), refus et échecs journalisés hors transaction (statut REFUS / ERREUR, code) ; révocation d'une délégation : propositions en attente ANNULEE.
- Cœur : `SpecialisationMcpBtp` (lot 10 : outils `proposer_validation`, `proposer_envoi`, `proposer_tiers`, `proposer_ventilation` avec `deposer`, exécuteurs `valider_piece`, `appliquer_ventilation`, `envoyer_document`, `creer_tiers_provisoire` de `Btp/McpPropositionsBtp.cs`, notification `SourcePropositionsAgents`, adresse `AdressesApp.UrlProposition`, `/api/mcp/propositions` en `ModeRoute.Session` ; lot 9 : `preparer_ordre_execution`, `preparer_demandes_appro` (BROUILLON) et `proposer_ventilation` (LECTURE) de `Btp/McpExecutionBtp.cs`, filtre `FiltreLignesOrdre`, routes de lecture `/api/execution/marches/{id}/selection-ordre`, `/api/execution/ordres/{id}/unites-stock`, `/api/stock/demandes/{id}/ventilation` ; lot 7 : outils composés BROUILLON `creer_devis`, `modifier_lignes`, `transformer` de `Btp/McpDocumentsBtp.cs` et `Btp/OperationsLignesBtp.cs`, `lire_document` composé pour COUTS sur les achats, origine AGENT dans `document_historique` par `db/309` ; lot 6 : outils de lecture `rechercher`, `lire_document`, `lire_marche`, `lire_chantier`, `rechercher_bibliotheque`, `lire_stock`, `lister_modeles`, `designer_tiers` ; nœuds retenus et clés sensibles du BTP ; module `mcp`, `db/308`), nœud `agents` (Consulter, Créer), `/api/mcp` Module sous `ExigeModule`, `…/revoquer` Action CREER, `/api/mcp/parametres` Parametrage ; écritures Action / Parametrage.

## Serveur d'autorisation OAuth 2.1 (lot 12, spécification MCP 2025-11-25)
- `db/099w_mcp_oauth.sql` (rejouable, manifeste) : `mcp_client_oauth` (liste blanche par société ; claude.ai et Claude Code pré-renseignés, désactivables), `mcp_oauth_autorisation` (demande 10 min, puis code 5 min à usage unique, empreinte seule), `mcp_oauth_rafraichissement` (empreinte seule, rotatif), `mcp_delegation.mde_client_oauth`.
- `LogiBTP.Mcp/ReglesOAuth.cs` (C# seul, sans miroir JS : le navigateur ne voit ni code ni jeton) : `ClientIdValide` (CIMD : https avec chemin), `ControlerDocument` (client public `none`, retours https ou boucle locale, `client_id` = adresse), `RedirectionPermise` (égalité exacte), PKCE S256 seul (`PkceValide`, temps constant), audience `Ressource` / `RessourceEgale` (`/mcp` de la société, RFC 8707), `EcheanceAcces` (15 min, bornées à la délégation) ; `ErreurOAuth` (codes de la norme).
- `ServiceOAuth` : métadonnées `/.well-known/oauth-protected-resource[/mcp]` (RFC 9728) et `/.well-known/oauth-authorization-server` (RFC 8414 ; 404 module inactif ou `SpecialisationMcp.AdresseConsentement` nul) ; `GET /api/mcp/oauth/authorize` (publique : le cookie SameSite=Strict ne vient pas du site du client) → page de consentement de l'application `?demande=…` ou `?erreur=CODE` (client hors liste ou document invalide, retour absent du document : jamais de redirection vers une adresse non vérifiée) ; erreurs suivantes rendues au client (`state`, `iss`) ; `GET /api/mcp/oauth/demandes/{d}` (client, retour, `ChoixDelegation`), `POST …/accepter` (délégation par `ServiceDelegations.PreparerAsync`, client = nom du document, code rendu dans `redirection`), `POST …/refuser` (`access_denied`) ; `POST /api/mcp/oauth/token` (publique, formulaire, client public seul ; `authorization_code` : même client et `redirect_uri`, PKCE, ressource ; `refresh_token` rotatif à usage unique) ; rejeu d'un code ou d'un jeton de rafraîchissement → délégation révoquée (`ServiceDelegations.RevoquerAsync(d, par, motif)` : jetons délégués, rafraîchissements, propositions) et `MCP_OAUTH_REJEU` au journal ; jeton d'accès = jeton délégué de `IJetonsDelegues.EmettreAsync` (15 min) : `/mcp` l'ouvre comme un jeton d'agent (même `Utilisateur.Agent`, plafond, journal). `GET|PUT /api/mcp/clients` : liste blanche (administrateur).
- `IDocumentsClients` / `DocumentsClientsHttp` (substituable) : document lu seulement pour un client de la liste blanche (5 s, 16 Kio, sans redirection, cache 10 min). Débit : politique `Extensions.PolitiqueDebitOAuth` (30 / min / adresse) ; `Extensions.RoutesPubliques` à déclarer publiques par l'application ; 401 de `/mcp` : `WWW-Authenticate: Bearer resource_metadata="<origine>/.well-known/oauth-protected-resource/mcp", scope="mcp"`.
- Cœur : `AdresseConsentement` = `AdressesApp.UrlAutorisationAgent` (`/agents/autoriser` ↔ `URL_AUTORISATION_AGENT`, `PageAutorisationAgent`), liste blanche dans `/parametres/agents`, routes publiques (`OptionsAuthentification.RoutesPubliques`, `ModeRoute.Publique`), `oauth/demandes` Module `agents`, `/api/mcp/clients` Parametrage ; écritures `token` Session, `demandes` Action, `clients` Parametrage.
