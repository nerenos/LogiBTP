# Module Pointage – contexte

## Rôle
- Heures de main-d'œuvre des salariés et intérimaires, toujours rattachées à un chantier (chantiers internes pour le temps hors chantier) et éventuellement à un ordre ([analyse](../../documentation/conception/ANALYSE-MODULE-POINTAGE.md)) : paramètres de la société, sous-types de main-d'œuvre (le type est une nature du regroupement main-d'œuvre, fournie par l'application), pointages saisis (couche SAISIE ; couche VALIDE de la synthèse au lot 2), contrôles d'une semaine.
- Ne connaît ni les salariés, ni les chantiers, ni les natures, ni les ordres : identifiants fournis par la spécialisation, clés étrangères posées par le cœur (`db/199`).

## Dépendances
- JS `@logibtp/pointage` : aucune. .NET : `LogiBTP.Pointage` (règles), `LogiBTP.Pointage.Web` → `LogiBTP.Socle.Web`, EF Core Npgsql. Jamais du cœur ni d'un autre module.
- Utilisé par : cœur (`SpecialisationPointageBtp` : salariés actifs et service principal, chantiers ouverts et internes, natures MO, services, ordres de la famille E si l'Exécution est active, droit de saisie ; `db/199` ; pages `client/src/app/pages/pointage.js`, liste `pointages`).

## Structure
- `js/src/controles.js` ↔ `dotnet/LogiBTP.Pointage/ReglesPointage.cs` (jeu `tests/cas/01_controles.json`) : `controlerSemaine` (par pointage : POI_CHANTIER, POI_TYPE, POI_MINUTES — 1 à 1440 —, POI_PAS, POI_PLAGE — début et fin cohérents avec la durée —, POI_MOTIF — non-conformité —, POI_CHANTIER_CLOS (avertissement) ; puis POI_CHEVAUCHEMENT par date ; puis POI_JOUR par date et POI_SEMAINE (avertissements) ; durées invalides hors des totaux), `bloquant`, `MESSAGES_POINTAGE`, `PARAMETRES_DEFAUT` ; JS seul : `lundiDe`, `joursSemaine`, `lireDuree` (« 7:30 », « 7h30 », « 7,5 » = heures décimales), `ecrireDuree`. C# : `LundiDe`.
- `js/src/validation.js` ↔ `dotnet/LogiBTP.Pointage/ReglesValidation.cs` (jeu `tests/cas/02_validation.json`) : `etatValidation` (jour couvert par une validation RH non annulée : VALIDE ; par une validation CHEF en mode DOUBLE : VALIDE_CHEF ; sinon NON_VALIDE — une validation CHEF en mode SIMPLE est ignorée), `estBloque`, `controlerAction` (VALIDER : VAL_CHEF_SIMPLE, VAL_RH_FAIT, VAL_DEJA ; DEVALIDER : DEV_MOTIF, DEV_RIEN, DEV_RH_FAIT), `exceptionsSemaine` (EXC_CORRECTION, EXC_SANS_POINTAGE, EXC_NON_CONFORMITE, EXC_HEURES_SUP au-delà du seuil, EXC_CONTROLE, EXC_MODIFIE), `ETATS_VALIDATION`, `MESSAGES_VALIDATION`.
- `js/src/paie.js` ↔ `dotnet/LogiBTP.Pointage/ReglesPaie.cs` (jeu `tests/cas/03_paie.json`) : `calculerVariables` (règles d'un profil dans l'ordre : CUMUL_HEURES { sous_types, exclure }, SEUIL_JOUR { base, seuil, valeur, exclu_si }, TRANCHES_SEMAINE { base, seuil, deduire, tranches [{ rubrique, jusqu_a }] } — semaine complète seulement —, ZONE { exclu_si } — zone la plus élevée du jour —, PLAFOND { max, max_semaine } ; saisies S avant les règles, SC après (0 annule), C ignorées ; totaux, zones comptées par numéro « ZONE_3 »), `controlerProfil` (PRF_RUBRIQUE, PRF_REGLE), `quantiteExport` (heures décimales à 2 chiffres), `TYPES_REGLE`, `UNITES_RUBRIQUE`, `SAISIES_RUBRIQUE`. Pas de règle FORMULE (langage d'expressions) pour l'instant.
- Unités : durées en minutes entières, heures de début et de fin en minutes depuis minuit, dates « AAAA-MM-JJ ».
- `db/086_pointage.sql` (rejouable) : `poi_parametre` (une ligne : ordre nom / prénom, pas, amplitudes jour et semaine, validation SIMPLE / DOUBLE, blocage JOUR / SEMAINE, intérimaires imputés), `poi_sous_type` (productif, non-conformité ; PRODUCTION, PREPARATION, TRAJET, ATTENTE, NETTOYAGE, NON_CONFORMITE), `poi_pointage` (couche, origine, salarié, date, chantier, ordre, ligne, type de MO, sous-type, début / fin, minutes, motif, commentaire, groupe d'équipe, tâche du planning, auteur, appareil, version).
- `db/087_pointage_validation.sql` (rejouable) : `ppa_seuil_semaine`, `poi_semaine` (semaine corrigée : la couche VALIDE remplace la saisie, même vide), `poi_validation` (période, niveau CHEF / RH, annulation par, le, motif), `poi_correction` (semaine demandée en JSON, motif, état EN_ATTENTE / APPLIQUEE / REJETEE, réponse), `poi_journal` (MODIFIER, RETABLIR, VALIDER, DEVALIDER, CORRECTION, CORRECTION_APPLIQUEE, CORRECTION_REJETEE).
- `db/088_pointage_paie.sql` (rejouable) : `poi_profil_paie` (exporté ou non), `poi_rubrique` (unité H / NB / ZONE, saisie C / S / SC, code de paie), `poi_regle` (type, rubrique, paramètres JSONB), `poi_valeur` (saisies par salarié, jour, rubrique), `poi_zone_chantier` (chantier, agence, zone 0 à 9, validée par), `poi_export` (période, service, salariés exportés, fichier CSV), valorisation sur le pointage (`poi_taux`, `poi_cout`, `poi_valorisation`, `poi_valorise_le`) ; profils OUVRIER, ETAM, INTERIM (non exporté).
- `dotnet/LogiBTP.Pointage.Web/ServicePointage.cs` : entités, `PointageDbContext`, DTO, `SpecialisationPointage` (`SalariesAsync`, `ChantiersAsync`, `TypesMoAsync`, `ServicesAsync`, `OrdresAsync`, `PeutSaisirAsync`), `ServicePointage` (paramètres et sous-types — administrateur, sous-type retiré utilisé = inactif —, référentiels, salariés d'un service avec leurs minutes par jour — couche validée prioritaire —, semaine d'un salarié — pointages saisis, chantiers récents, ordres, contrôles —, enregistrement de la semaine — couche SAISIE remplacée, erreurs refusées en 422 avec la liste des contrôles, version incrémentée —, position d'un pointage) ; `Retenus` (couche validée des semaines corrigées, sinon saisie), `EtatsAsync` (états des sept jours) ; la saisie refuse en 409 `POI_VALIDE` toute modification d'un jour validé. `ServiceSynthese.cs` : synthèse d'une semaine (RH : tous les salariés ; chef : ceux de ses services), détail (saisie, couche validée, validations, corrections, journal), couche validée écrite par le chef (avant sa validation) ou le RH (avant la sienne), retour à la saisie, valider / dévalider une sélection (période = semaine si le blocage est à la semaine), demandes de correction (créées par qui peut saisir, appliquées ou rejetées par le RH ; `ApresCorrectionAsync`). Spécialisation : `EstRhAsync`, `ChefDeAsync`, `JoursTravaillesAsync` (défaut : lundi à vendredi), `TauxAsync` (lot 3) ; synthèse : EXC_ZONE si un chantier pointé n'a pas de zone pour l'agence du salarié (profil à règle ZONE). `ServicePaie.cs` : profils (administrateur ; retiré = inactif), variables d'une semaine (contexte chargé en une fois : retenus, saisies, zones, validations RH ; semaine complète = validée ou passée), saisies des rubriques, zones (RH), export CSV (« ; », virgule décimale, semaines entières, jours tous validés RH, profils exportés ; enregistré : `poi_export`, une dévalidation ultérieure est signalée `apres_export`), valorisation (mode SALARIE : taux de la spécialisation, intérim seulement si `ppa_interim_imputes` ; IMPORT : matricule → coût horaire réel). `Extensions.cs` (`AddModulePointage<T>`, `MapModulePointage`).

## Routes HTTP (préfixe `/api/pointage`, module activé par société)
- `GET|PUT /parametres`, `GET|PUT /sous-types`, `GET /referentiels`, `GET /chantiers?recherche=`, `GET /salaries?service=&recherche=&lundi=`, `GET /pointages/{id}/position`, `GET|PUT /semaine/{salarie}/{lundi}` ; synthèse : `GET /synthese?service=&recherche=&lundi=`, `GET|PUT|DELETE /synthese/semaine/{salarie}/{lundi}`, `POST /synthese/valider|devalider` { salaries, lundi, du, au, motif }, `POST /corrections`, `POST /corrections/{id}/appliquer|rejeter` { reponse } ; paie : `GET|PUT /profils`, `GET|PUT /variables/{salarie}/{lundi}`, `GET|PUT /zones/{chantier}`, `GET /export?du=&au=&service=` (aperçu), `POST /export`, `GET /exports`, `GET /exports/{id}/fichier`, `POST /valoriser` { du, au, service, mode, taux }.
