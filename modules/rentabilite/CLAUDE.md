# Module Rentabilité – contexte

- Détail à lire avant de toucher une partie (inventaire des fichiers, modèle de données, points de spécialisation, routes) : [RENTABILITE.md](../../documentation/modules/RENTABILITE.md).

## Rôle
- Suivi économique des chantiers ([analyse](../../documentation/conception/ANALYSE-MODULE-ANALYSE.md)) : indicateurs budget, budget d'exécution, engagé, déboursé, facturé, par chantier, ordre d'exécution et nature, calculés en **faits** (une donnée élémentaire datée par ligne de pièce, pointage, tâche ou mouvement de stock) que la page des faits et le rapprochement montrent tels quels.
- Sans métier : ne connaît ni les chantiers, ni les pièces, ni les natures ; le cœur fournit les faits et les axes par `SpecialisationRentabilite` (cœur : `src/LogiBTP.Api/Btp/RentabiliteBtp.cs`). Module facultatif `rentabilite` de `module_societe` (`db/258`).

## Dépendances
- JS `@logibtp/rentabilite` → `@logibtp/socle`. .NET : `LogiBTP.Rentabilite` (codes, faits, comparaison), `LogiBTP.Rentabilite.Web` → `LogiBTP.Socle.Web`, EF Core Npgsql. Jamais du cœur ni d'un autre module.
- Utilisations par le cœur : voir le détail.

## Repères
- Faits versionnés (`rentabilite_fait`) jamais effacés : un fait disparu est clos par le calcul suivant ; une photo référence un calcul, jamais une copie.
- Un chantier se recalcule entier, dans une transaction sous verrou consultatif ; la file `rentabilite_a_recalculer` n'est remplie que par les triggers du cœur (`f_rentabilite_signaler`) ; changer `VersionRegles` recalcule les chantiers ouverts.
- Faits `PREVU_*` des saisies prévisionnelles écrits par le module, jamais mélangés au réel.
- PA / PR masqués sans le droit `rentabilite/couts` ; pièces d'un type non consultable résumées.
- Parité : `codes.js` ↔ `Codes.cs` (`CodesTests`), `periodes.js` ↔ `Periodes.cs` (jeu 01), `facturation.js` ↔ `Facturation.cs` (jeu 02) ; calculs en décimal, jamais en `Number`.

## Textes et icônes
- Textes, icônes et couleurs par `js/personnalisation/` (règles et exceptions gardées en littéraux : voir le détail).

## Tests
- `npm test --workspace modules/rentabilite/js` ; `dotnet test modules/rentabilite/dotnet/LogiBTP.Rentabilite.Tests` (parité des codes, comparaison des faits).
