# Module GED – contexte

## Rôle
- Documents stockés sur le serveur (contenus rangés par empreinte SHA-256, dépôts identiques partagés), liés à un élément quelconque (`type_element`, `id_element`), classés dans des répertoires, versions, aperçu, mails (.eml / .msg avec pièces jointes), suppression par masquage, coffre-fort (journal chaîné immuable).
- Versions de deux genres : `etape` (VALIDATION, ENVOI, RECEPTION, SIGNATURE, REFUS, ARCHIVAGE) toutes conservées ; `edition` (dépôts, modifications) dont seules les N dernières sont gardées (`editions_conservees`, 5 par défaut).
- Cycle de vie : confidentialité et accès, texte extrait et indexé (plein texte), classification automatique au dépôt, dérivations entre documents, rétention (archivage puis fin de conservation) et archive séparée.
- Explorateur à la façon de l'explorateur Windows : arbre (nœuds automatiques fournis par l'application + répertoires créés), chemin servant de filtre (Entrée : recherche dans toute la GED), vue icônes ou détails triable, visualisation avec dock bas d'informations.

## Dépendances
- Dépend de : socle (`@logibtp/socle` : `echapper`, `creerCombo`, préférences ; `LogiBTP.Socle.Web` : `Utilisateur`, `ExceptionMetier`, `SocieteCourante`) ; `postal-mime`, `@kenjiuno/msgreader` (chargés au premier mail) ; PdfPig 0.1.16 (C#, texte des PDF).
- Utilisé par le cœur : `SpecialisationGedBtp` (`src/LogiBTP.Api/Btp/SpecialisationsElements.cs`, config `Ged:Repertoire`, `Ged:TailleMaxDepotMo`), `Program.cs` (`AddModuleGed<SpecialisationGedBtp>`, `AddArchivageGed` (section `Ged:Archivage`), `MapModuleGed`) ; client `client/src/app/ged/ged.js` (`creerFournisseurGed`, démo semée, catégorie `notice_technique` DOE), `ged/arborescence.js` (`ArborescenceBtp` : structure des affaires et documents), pages `ged.js`, `parametres-ged.js` (`/parametres/ged`, menu Paramètres › GED : rétention et classification), `fiche.js` (onglet compact), `document.js` (onglet Pièces), fiche élément de bibliothèque (`image_ged`, notices), import (fichier source, catégorie `import`).

## Modèle de données
- `contenu_ged` (`cge_empreinte` PK CHAR(64), taille, chemin) ; `document_ged` (`dge_*` : titre, categorie, nature `fichier|mail`, `dge_type_element` / `dge_id_element`, `dge_parent_id` = pièce jointe d'un mail, `dge_mail` JSONB, resume, notes, `dge_etat`, `dge_coffre`, `dge_a_envoyer`, `dge_supprime*`) ; `version_ged` (`vge_*`, unique `(vge_document, vge_numero)`, genre, etape, empreinte → contenu) ; `coffre_ged` (`cof_*` : empreinte du document, horodatage, utilisateur, motif, `cof_empreinte_precedente` unique, `cof_empreinte_entree` unique, `cof_document` unique, empreintes hexadécimales minuscules) ; `parametre_ged` (`editions_conservees`, `taille_apercu_max`, `adresse_copie_cachee`, `categories` avec drapeau `coffre`).
- 051 sur `document_ged` : `dge_repertoire_id` (même élément que le répertoire, `tr_ged_document_repertoire`), `dge_confidentialite` (PUBLIC, INTERNE, CONFIDENTIEL, SECRET), `dge_acces_profils` / `dge_acces_utilisateurs` (TEXT[]), `dge_texte_contenu`, `dge_mots_cles` (TEXT[]), `dge_langue`, `dge_index_etat` (A_FAIRE, FAIT, SANS_TEXTE, ECHEC), `dge_indexe_le`, `dge_classification` (JSONB), `dge_nb_versions` / `dge_version_courante` (déclencheur `tr_ged_compteur_versions`), `dge_archive` / `dge_archive_le` (archivage sur place, coffre seulement), `dge_plein_texte` (tsvector généré pondéré : `f_ged_plein_texte`, texte normalisé, configuration française).
- `repertoire_ged` (`rge_*` : nom unique sans casse parmi les frères, parent, élément repris du parent, sans boucle) ; `derivation_ged` (`drg_*` : source, cible, type VERSION / TRADUCTION / ADAPTATION / EXTRAIT / ANNOTATION, langue, sans boucle) ; `regle_retention_ged` (`rrg_*`) ; `regle_classification_ged` (`rcg_*`) ; `document_ged_archive` / `version_ged_archive` (mêmes colonnes + `dga_archive_le`, `dga_archive_par`, `dga_motif`, `dga_derivations` JSONB ; contenus retenus par clé étrangère).
- Triggers : `tr_coffre_immuable` (ni UPDATE ni DELETE sur `coffre_ged`), `tr_document_coffre` (pas de DELETE ni de sortie du coffre), `tr_version_coffre` (versions d'un document du coffre conservées), `tr_*_vidage` (TRUNCATE interdit sur les trois tables), `tr_ged_element_existe`, `tr_ged_parent_sans_boucle`, statistiques, 051 : `tr_ged_repertoire`, `tr_ged_document_repertoire`, `tr_ged_compteur_versions`, `tr_ged_derivation_sans_boucle`. Messages `GED_CODE : texte` (traduits par `ServiceGed.Traduire`).
- Vue `v_liste_ged` (documents actifs, non archivés, PUBLIC ou INTERNE sans accès listés + dernière version) pour le module Liste, qui n'applique pas les accès de la GED.

## Points de spécialisation
- `SpecialisationGed` (C#) : `RepertoireStockage` (racine ; un sous-répertoire par société nommé comme sa base : `logibtp`, `logibtp_demo`… via `SocieteCourante.Base`, `Extensions.RepertoireSociete`, ancien dossier au nom du code renommé au premier accès), `TailleMaxDepot` (200 Mo), `Visibles(query, u)` (appliqué après le filtre d'accès `AccesGed.Filtre`), `PeutDeposer`, `PeutModifier`, `PeutPurger` (admin ; aussi règles, rétention, indexation en lot), `PeutSupprimerCoffre` (admin), `ControlerDepot(meta, nom, taille, u)`.
- `ServiceGed` : méthodes `virtual` (Lister, Document, Deposer, DeposerFichier (fichier déjà lu : productions de l'application, éditions PDF), LireContenu (contenu courant lu par l'application : images des éditions), NouvelleVersion, Etape, Modifier, MettreAuCoffre, Verifier, VerifierCoffre, Supprimer, Restaurer, Purger, Contenu, Repertoires, CreerRepertoire, ModifierRepertoire, SupprimerRepertoire, AjouterDerivation, SupprimerDerivation, Indexer, IndexerEnAttente, Echeances, AppliquerRetention, Archiver, RestaurerArchive, Regles, RemplacerReglesRetention, RemplacerReglesClassification).
- `ExplorateurGed(conteneur, { fournisseur, contexte: { type_element, id_element, libelle, icone } | null, arborescence, compact, modifiable, admin, utilisateur, message, documentInitial, coffre, envoi, ouvrirUrl })` : `contexte` null = GED globale ; `arborescence` : instance d'`ArborescenceGed` (méthode patron `racine()`, `enfants(noeud)` ; nœud `{ cle, libelle, icone, sous_titre, element, groupe, lien: { cle, chemin }, url }`) ; `envoi` = case « 📧 » (`dge_a_envoyer`, module Mail à venir) ; `compact` = vue des fiches (arbre masqué par défaut) ; préférences du navigateur sous `ged` / `gedCompact` (largeurs, hauteur et visibilité du dock, onglet, vue, tri).
- `DialogueDepot(fichiers, { fournisseur, destination: { type_element, id_element, repertoire_id, libelle }, utilisateur, parametres, message, surTermine })` : informations communes ou par fichier, catégorie proposée (`classer` sur les métadonnées ; le serveur reclasse avec le texte quand la catégorie n'est pas choisie).
- Fournisseurs : `FournisseurGedApi({ base: '/api/ged', entetes })` ou `FournisseurGedMemoire({ utilisateur, profil, parametres, horloge, elementExiste, reglesRetention, reglesClassification })` (tests ; mêmes règles que `ServiceGed`, recherche par mots sans racines françaises).
- `ParametrageReglesGed(conteneur, { fournisseur, admin, message })` : deux tableaux (rétention, classification) remplacés en bloc par `remplacerReglesRetention` / `remplacerReglesClassification` (contrôles du serveur ou du fournisseur mémoire, messages d'erreur affichés) ; combos du socle (`creerCombo`) pour catégorie, action de fin, confidentialité ; ↑↓ échangent aussi les priorités ; nombre de documents échus (`echeances()`) ; `modifie` (garde de la page) ; lecture seule sans `admin`.
- Archivage automatique : `AddArchivageGed(configuration.GetSection("Ged:Archivage"))` (après `AddSocietes` et `AddModuleGed`) enregistre la tâche de fond `ArchivageGed` ; options `Actif` (false : désactivée), `Heure` (`HH:mm`, heure locale du serveur, 02:30 par défaut), `Utilisateur` (code de l'utilisateur système, profil ADMIN, inscrit au journal de l'archive). Chaque nuit, pour chaque société (`OptionsSocietes.Societes()`), une portée `CreerPorteeSociete` puis `ServiceGed.AppliquerRetention` ; une base en erreur est journalisée sans arrêter les suivantes. `ArchiverAsync` (un passage, public pour les tests) et `DelaiAvant` (prochain passage).
- Rattachement des documents du cœur : `type_element` = `tyd_code` du type de document, `id_element` = `ent_groupe_id ?? ent_id` (groupe des indices) ; `salarie`, `materiel`, `element` (bibliothèque), `projet`, `affaire`, `chantier`, `marche`, `personne`, `individu`.

## Règles répliquées JS / C# et jeux de cas
- Chaîne du coffre : `coffre.js` ↔ `ChaineCoffre.cs` ; texte d'entrée `precedente|empreinte_document|horodatage|document|version|utilisateur|motif`, horodatage ISO UTC à la milliseconde (`ChaineCoffre.Tronquer`) ; jeu `tests/cas/01_coffre.json`.
- Conservation des versions : `versions.js` ↔ `RegleVersions.cs` (courante jamais purgée, rien au coffre) ; jeu `02_versions.json`.
- Normalisation de recherche : `recherche.js` ↔ `NormalisationGed.cs` ↔ `f_ged_normaliser` (SQL) ; jeu `03_normalisation.json`.
- Rétention : `retention.js` ↔ `RegleRetention.cs` (règle la plus précise : catégorie et type, catégorie, type, aucune ; puis priorité, id ; mois ajoutés avec fin de mois ramenée) ; jeu `04_retention.json` ; règles par défaut identiques aux INSERT de 051.
- Classification : `classification.js` ↔ `ClassificationGed.cs` (tous les critères renseignés ; catégorie de la première règle, confidentialité la plus stricte, mots-clés cumulés) ; jeu `05_classification.json` ; règles par défaut identiques aux INSERT de 051.
- Accès : `acces.js` ↔ `AccesGed.cs` (auteur du dépôt et accès listés toujours ; SECRET : personne d'autre ; CONFIDENTIEL : + administrateurs ; PUBLIC / INTERNE : tous sauf accès listés) ; jeu `06_acces.json`.
- `FournisseurGedMemoire` reproduit `ServiceGed` (codes `ErreurGed` : INTROUVABLE, COFFRE, SUPPRIME, ACCES_REFUSE, DOUBLON, REPERTOIRE_NON_VIDE, REPERTOIRE_BOUCLE, REPERTOIRE_ELEMENT, DERIVATION_BOUCLE, ARCHIVE_PIECE, NON_ARCHIVE…).

## Conventions et pièges
- Ne jamais contourner les triggers de `db/050` (pas de DELETE / TRUNCATE / désactivation de trigger, pas de « sortie » du coffre, même en script de démo ou de test). L'archive séparée ne prend jamais un document du coffre : une famille (mail + pièces) qui en contient un est archivée sur place (`dge_archive`).
- Document au coffre : aucune nouvelle version ni étape, ni changement d'élément lié ; seules les informations de classement changent (résumé, notes, à envoyer, confidentialité, accès, mots-clés, langue, répertoire du même élément) ; mise au coffre refusée si le contenu recalculé diffère (`INTEGRITE`).
- Confidentialité et accès : modifiables par l'auteur du dépôt ou un administrateur. Saisie au dépôt prioritaire sur la classification.
- Répertoire : un document classé dans le répertoire d'un autre élément est lié à cet élément (les pièces jointes d'un mail suivent) ; un répertoire se déplace sous le même élément ; suppression d'un répertoire vide seulement.
- Purge : document déjà masqué (`NON_SUPPRIME` sinon), jamais au coffre, dérivations retirées ; masquer un mail masque ses pièces jointes. Contenu orphelin : ni version active ni version archivée.
- Contenu servi (`GET /versions/{id}/contenu`) : le type MIME vient du dépôt, donc jamais de confiance ; `inline` seulement par `AffichageContenu`, toujours `X-Content-Type-Options: nosniff` et `Content-Security-Policy: sandbox` (un HTML ou un SVG ouvert dans un onglet n'exécute rien dans l'origine de l'application). Aperçu : le cadre ne reçoit qu'un PDF (type imposé), sans attribut `sandbox` (Chrome et Edge n'y affichent plus le PDF) ; images par `<img>`.
- Dépôt multipart lu par le service (pas de liaison `IFormFile`, `DisableAntiforgery`) ; ne jamais poser le Content-Type d'un FormData.
- Bases existantes : appliquer 051 aux deux bases, puis `POST /api/ged/indexation` (administrateur, par lots) pour indexer les documents déjà déposés.
- Toute modification d'une règle répliquée : les deux côtés + le jeu de cas.
- Archivage automatique : l'utilisateur système passe par le filtre d'accès (`AccesGed`) comme un administrateur ; un document SECRET dont il n'est ni l'auteur ni un accès listé n'est donc pas archivé automatiquement (à faire à la main par son auteur).
