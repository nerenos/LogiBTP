# Module Document – contexte

## Rôle
- Document commercial générique (sans métier BTP) : entête, arbre de lignes, pied en tranches, TVA par catégorie, numérotation, statuts, indices, copies, transformations, verrou, historique, traçabilité, affichage de la saisie.
- Cycle : création en BROUILLON → validation (statut VALIDE, verrouillé) ; indices A, B… d'un même groupe (un seul de référence) ; copie = nouveau document, indice A, lien COPIE.
- Fournit des classes mères (méthode patron) que le cœur spécialise ; moteur de calcul répliqué JS / C#.

## Dépendances
- Dépend de : `@logibtp/socle` (JS : `Dec`, `arrondir`, `remplacerVariables`… ; ui : `Magasin`, `GrilleArbre`, `CFG_LIGNES`, `editerLibelle`, préférences), `LogiBTP.Socle` / `LogiBTP.Socle.Web` (`Utilisateur`, `ExceptionMetier`), EF Core Npgsql, HtmlSanitizer. Jamais du cœur.
- Spécialisé par le cœur : `MoteurDevisBtp` (JS `client/src/calcul/moteur-btp.js`, C# `src/LogiBTP.Calcul`), `EditeurDevisBtp` / `ReglesBtp` / `PressePapiersBtp` (`client/src/app/editeur-btp.js`), `PanneauxBtp`, `SpecialisationBtp` + `DocumentCompletBtp` + `LogiBtpContext` (`src/LogiBTP.Api/Btp`), branchés dans `Program.cs`.
- Utilisé par : cœur seul (`client` : `@logibtp/document` ; `LogiBTP.Domaine` → `LogiBTP.Documents`, `LogiBTP.Api` → `LogiBTP.Documents.Web`). Métré est indépendant (le cœur fait le lien). Aucun autre module n'importe Document.

## Modèle de données
- Paramétrage : `type_document` (`tyd_famille` V/A/S, `tyd_sens`, `tyd_numerotation_continue`, `tyd_handler` NULL = Standard, `tyd_validite_jours`), `statut_document` (`std_modifiable`, `std_terminal` ; codes BROUILLON, VALIDE), `propriete_definition` (niveau E/L, types texte/entier/decimal/date/booleen/liste), `taux_tva` (`ttv_categorie` N/A/I/E), `transformation_autorisee` (`tra_etape`, `tra_vaut_etapes[]`), `droit_document` (CREER, MODIFIER, VALIDER, TRANSFORMER, SUPPRIMER), `compteur_numero`, `unite`.
- `document` (`ent_*`) : numéro, date, objet, références, `ent_validite_jours` / `ent_date_validite`, `ent_std_id`, `ent_tiers_id`, adresses JSONB copiées, `ent_num_format` JSONB, `ent_precision_montant`, totaux NUMERIC(18,6), `ent_proprietes` JSONB, `ent_groupe_id` + `ent_indice` + `ent_is_reference` (indices), `ent_verrouille`, `ent_copie_de_id`, `ent_version` (optimiste), `ent_modele`, `ent_etiquettes`.
- `document_ligne` (`lig_*`) : `lig_parent_id`, `lig_chemin` LTREE (trigger), `lig_ordre`, `lig_tyl_id`, numérotation (`lig_num_depart`, `lig_num_manuelle`), libellés html/affiché/brut, `lig_qte` + `lig_qte_type` R/A, `lig_pv`, `lig_coef_remise` (0,90 = 10 %), `lig_type_prix` V/O/M/A/F (F frais annexes, `014`), `lig_variante_de_id`, `lig_st_depuis_id`, pied (`lig_pied_mode` P/M/C, `lig_pied_base`, `lig_pied_base_id`, `lig_pied_sens`, `lig_pied_valeur`, `lig_base_calcul`), TVA, `lig_origine_id`, `lig_proprietes`, `lig_etiquette`.
- TL (`011`, ids fixes) : 1 TITRE, 2 OUVRAGE, 3 ELEMENT, 4 TEXTE, 5 SOUS_TOTAL, 6 IMAGE, 7 SAUT_PAGE, 8 PIED_HT, 9 PIED_TTC, 10 TVA, 11 SECTION.
- Liens : `document_lien` (TRANSFORMATION | COPIE), `document_ligne_lien` (`lil_etape`, `lil_qte` négative pour retour, avancement % / qté), `document_ligne_solde`. Étapes facultatives RETOUR, AVOIR.
- Transformation (tout le reliquat) : toutes les lignes de prix reprises, à 0 quand plus rien ne reste ; une cible est aussi liée aux lignes d'origine de sa source (facture d'un BL → commande) ; `lil_qte` / `lil_montant_ht` recalculées à chaque enregistrement de la cible (`DocumentService.RecalculerLiens`, hors avancements). Validation : une ligne soldée (`lig_solde`) ou sous le seuil (`parametre_document.seuils_solde`, achats / ventes, % et quantité) écrit `document_ligne_solde` avec `lso_cible_lig_id` (retiré par un avoir ou la suppression de la ligne). Options et variantes : `DemandeTransformation.Choix` ([{ lig_id, retenue }]) obligatoire pour chaque unité (`OPTION_NON_TRAITEE`), retenue → type V sans `lig_variante_de_id`, base d'une variante écartable, pour mémoire repris ; choix dans `document_lien.lie_choix` ; étape COMMANDE → source au statut ACCEPTE s'il existe. Type intermédiaire (`tra_intermediaire_tyd_id`) : `Transformer` crée l'intermédiaire, le valide (`DocumentService.ValiderDans`, sans droit VALIDER) puis le transforme, dans une transaction. Client : `EditeurDocument.definirRestes` (colonnes `COLONNES_RESTE` : qte_parent, reste, solde ; ajoutées après la quantité si la vue n'en a aucune ; ligne déjà soldée ailleurs : `ligne-soldee`).
- `document_origine` (IMPORT, format, fichier GED, rapport) ; `document_historique` (CREATION, MODIFICATION, VALIDATION, ANNULATION ; `his_instantane` JSONB lz4 de l'état avant) ; `document_tva` ; `calcul_cas_test` (écarts client/serveur arbitrés S/A).
- `verrou_document` (`vdo_jeton` UUID par fenêtre, sans expiration).
- `013` : `etiquette_ligne` (globales ; `ent_etiquettes` complète par document), `couleur_type_prix` (O/M/A/F, seconde couleur de la pastille).
- Type de prix hérité par toute la descendance (choisi aussi sur une tranche dans le détail) ; F (frais annexes, proposé sur un titre seulement) : hors total comme une option, `lig_is_non_editee` forcé par les moteurs (`estFraisAnnexes`), sans numéro (`estNumerotee`), montant de la tranche F = ses frais (italique : `tranche-frais` dans la grille et le plan, `complementTranche` de l'éditeur) ; ventilation dans les prix par la spécialisation. Transformation : les tranches F sont conservées ; `SpecialisationDocument.PreparerValidation` (résultat avant enregistrement de la validation). Pastille de la grille et demi-pastille du plan selon le type effectif (`EditeurDocument.typePrixEffectif` / `pastilleTypePrix`).
- `013` : `modele_document` (COMPLET, CHIFFRAGE, VOLEE), `vue_document` (`vdo_definition` { colonnes: [{ cle, largeur? }], debogage, systeme } ; globale si `vdo_proprietaire` NULL, une par défaut par type × modèle).
- Colonnes métier ajoutées par le cœur (`ALTER TABLE` dans `db/`) ; entités C# étendues par héritage (`DocumentBtp`, `DocumentLigneBtp`).

## Conventions et pièges
- Ne jamais comparer `lig_tyl_id` numériquement : utiliser les prédicats (`estPied`, `estTranche`…). SECTION : racine seulement (`SECTION_RACINE`), pied à la racine ou dans une section à la racine (`PIED_RACINE`).
- Pieds de section : `passePied` → `calculerPortee(lignes, elements)` par section qui porte un pied (`pieds_sections` : [{ lig_id, pied }]) et pour le reste, puis `consoliderPied` (entrées `genre: 'consolide'` : libelle, mode, sens, base, taux commun ; TVA additionnée par code ; postes TTC et sous-totaux de pied de la racine) ; sans pied de section, calcul inchangé (une portée). C# : `CalculerPortee`, `ConsoliderPied`, `ElementPied`, `PiedSection`, `EntreePied` étendu. Grille : `lignesPied` → `structurePied` / `ligneVirtuelle` (identifiants : tranche de section `ID_PIED − (k + 1)`, lignes décalées de (k + 1)·10⁹).
- Codes d'erreur moteur à garder identiques (ex. `VARIABLE_INCONNUE`, `TVA_MANQUANTE`, `TVA_DOUBLE`, `PIED_BASE`, `SOUS_TOTAL_POINTE`, `PRIX_INTERDIT`, `QTE_NON_CALCULEE`) ; services : `VERSION` (409), `DOCUMENT_BLOQUE`, `DOCUMENT_VERROUILLE`, `DOCUMENT_LIE`, `DOCUMENT_VALIDE`, `TIERS_OBLIGATOIRE`, `CONTROLES`, `VALIDATION`, `TRANSFORMATION_INTERDITE`, `SOURCE_NON_VALIDEE`, `RIEN_A_TRANSFORMER`.
- Numéro : à la création sauf `tyd_numerotation_continue` (factures, avoirs : à la validation). Validation : statut VALIDE, `ent_verrouille`, `ent_date_validite` = aujourd'hui + jours (serveur).
- Enregistrement : l'entête saisi est recopié champ par champ (ajouter les champs métier dans `CopierEnteteSaisie`) ; libellés HTML nettoyés par `NettoyageHtml` ; ID négatifs temporaires → `CorrespondanceLignes`.
- Suppression bloquée si le document est la source d'une TRANSFORMATION ; un brouillon cible se supprime avec ses liens (COPIE retiré avec le document).
- Avancement : `MoteurDocument.avancement(l)` (quantité et montant de la ligne = cumul ou période selon `ent_avt_presentation`, sorties `lig_avt_montant_cumul`, `lig_avt_pct`, `lig_avt_qte_cumul`) ; `TransformationService.PreparerAvancement` (ligne du marché, précédent, saisie initiale = montant précédent, % pour une ligne sans prix) ; `DocumentService.Precedents` / `AppliquerPrecedents` (dernier document validé non annulé en présentation P ou de type R) ; liens d'une situation à quantité 0 ; type `tyd_avancement` S / F / R ; colonnes de grille `COLONNES_AVANCEMENT` (saisie `avt:P|Q|M`).
- Avancement, suite : `avancementPied` (poste de pied en montant, mode A au prorata de l'avancement global de la portée) ; validation : facture d'avancement à période négative → type `tyd_avoir_tyd_id`, `ent_nature_avoir` AVANCEMENT ; `ent_etat_compta` des pièces à numérotation continue ; `CreerIndice` d'une situation validée (`tyd_avancement` S) = nouvelle référence (`SITUATION_FACTUREE`) ; la réponse de validation est relue après les soldes et `ApresValidationAsync`.
- Annulation : `AnnulerParAvoirDans` (type `tyd_avoir_tyd_id`, ou le type de l'avoir pour un avoir d'avancement ; nature ANNULATION ; `ValiderDans` puis statut ANNULE des deux pièces ; `ANNULATION_IMPOSSIBLE`) ; `document_lien.lie_type` ANNULATION (`019`).
- Plusieurs sources : `TransformerPlusieurs`, `AjouterSources` (`DocumentService.EnregistrerDans`), `EnAttente` ; `Preparer` (une source : options, retenues, lignes gardées ; reste = minimum des étapes couvertes), `ContenuSource` (`RenumeroterTemporaire(d, ref n)`), `EnSection`, `Fusionner`, `EcrireLiens` ; `SOURCE_DEJA_REPRISE`, `SOURCES`.
- Colonne Commentaire (`lig_commentaire`, première ligne dans la grille, zone de texte dans le détail) ; `lig_cpt_code` sans règle dans le module (colonne Compte et compte hérité : cœur).
- Lignes virtuelles du pied : `_virtuelle`, `ID_PIED` (−9·10¹¹), ids ≤ −10¹², jamais saisissables.
- Verrou sans expiration : seul `PeutDeverrouiller` (admin par défaut) force. `Disposition` cherche dans `racine` (deux pages coexistent pendant une ouverture).
- Commentaires anciens citent `LogiBTP.Document(.Tests)` : les projets s'appellent `LogiBTP.Documents*`.
