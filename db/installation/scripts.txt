# Source unique de l'ordre : base de développement (docker-compose.yml, initialiser-developpement.sh) et installeur
# (commande « installation base creer | mettre-a-jour »). Un chemin par ligne, relatif à la racine du dépôt, suivi
# d'un indicateur facultatif :
#   rejouable : rejoué à sa place à chaque mise à jour (sinon appliqué une seule fois, inscrit dans installation_script).
#     Ne se marque que s'il peut être rejoué sans rien changer (repérage empirique : scripts/reperer-rejouables.sh) et s'il
#     ne réécrit aucune donnée que la société peut modifier (ni UPDATE, DELETE, ni INSERT : seuls les scripts de pur DDL,
#     et les scripts générés 121, 131, 191, dont la réécriture est voulue).
#   Le manifeste se parcourt dans l'ordre ; un chemin peut y figurer deux fois (non rejouable, puis rejoué plus bas).
#   ex-rejouable : ancien rejouable devenu non rejouable (jamais inscrit au journal) : inscrit sans exécution sur une
#     base déjà installée, appliqué sur une base neuve (267, 287 : vue étendue par un script suivant).
#   demo : script de données de démonstration (tiers, chantiers, salariés… fictifs) : appliqué seulement si l'application est
#     demandée avec la démonstration (installation base creer|societe ajouter --demo ; mise à jour : seulement les bases qui
#     en ont déjà reçu un) ; initialiser-developpement.sh et scripts/demo/initialiser-base-demo.sh appliquent tout. Combinable
#     avec rejouable. Les données de référence dont dépendent les scripts suivants restent hors démonstration.
#   extrait-de=CHEMIN : script extrait d'un script déjà publié (réduit depuis). Sur une base dont le journal porte l'ancienne
#     empreinte de CHEMIN (empreintes-acceptees.txt), il est inscrit sans exécution (son contenu est déjà dans la base).
# Tout script de modules/*/db et db/ doit y figurer (test LogiBTP.Installation.Tests).
